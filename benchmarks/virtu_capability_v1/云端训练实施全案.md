**项目**：Virtu-CAD/CAM 工业智能体模型（品牌名 "Virtu-Omni-10B"，实际权重 = Qwen3-8B + LoRA）
**文档编号**：VIRTU-TRAIN-2026-1031-R01
**编制日期**：2026-10-31
**版本**：v1.0（待评审）
**密级**：内部
**依据**：《AI模型系统性能力测评报告》VIRTU-EVAL-2026-1031 的实测短板清单 + 本仓库云端实测记录
**适用环境**：damodel 按小时租用的单卡 GPU 实例（本项目历史实测：1× NVIDIA L40S）+ 本地 RTX 4050 工作站（合并/量化/部署验证）

> **本案的两条硬约束来自实测，不是假设**
> ① 云端只有 1 张卡、无 RDMA/IB，任何"TP×PP×DP 128 卡"配置在本项目里不可执行；
> ② 本地 6GB 显卡无法承载 8B 推理测评（实测：权重载入 3–12 min，生成 1–2 tok/s，一次 3 例冒烟在 0% GPU 利用率下 20 min 未产出）。
> 因此**训练与测评推理一律在云端跑**，本地只做合并、量化、部署验证。

## 2. 数据集选型标准

### 2.1 红线：训练数据与评测集必须隔离

- **禁止**把 `data/benchmark/virtu_eval_v1/*.jsonl` 的任何 prompt/gold/criteria 文本或其改写写入训练语料。
- 落地质检：`virtu_eval/contamination_check.py`（本案新增脚本要求）——对训练集逐条计算与 240 条用例的
  ①完整 prompt 归一化哈希相同；②n-gram(8) Jaccard ≥ 0.6；③gold 答案数值串在训练样本中出现。命中任一条即**剔除该训练样本并阻断发布**。
- 每个 Stage 的评测必须用**未参与该 Stage 训练的另一半用例**做交叉验证：240 条按 `case_id` 哈希对半切 A/B 两折，训练期看 A 折、发布看 B 折，避免"用同一份题调出来的分数"自证。

### 2.2 各 Stage 数据选型标准

| Stage | 数据类型 | 规模（token） | 来源与选型标准 | 质检门槛 |
|---|---|---|---|---|
| S1 领域知识 | 指令-回答对（GD&T、公差配合、材料切削性、标准条款释义、六软件 API 语义） | 8–12 M | ①本仓库 `data/` 已入库工业语料；②标准原文条款的**自查重写**（不复制整份标准，避免版权与出处不清）；③教师模型蒸馏（ModelScope 免费推理网关，需 `ms-` token，走文件交接，不入仓） | 去重（SQLite 批处理管线已存在：`feat(corpus)` 那版）；每题必须带**出处字段**；无出处样本丢弃 ≥ 5% 抽检 |
| S2 工具编排 | (用户中文意图, 工具 schema, 期望 tool_call JSON) 三元组 | 2–3 M | 工具名与参数**必须**来自仓库真实定义：`checkpoints/tool_agent_lora_final/industrial_agent_tools.json`、`bridges/tool_calling_specs.py`。禁止为凑数新造工具名 | schema 可解析率 100%；参数值可从 prompt 反查（不可反查的样本丢弃）；含 10% "无工具可用"负样本 |
| S3 边界与安全 | 缺项/矛盾/幻觉诱导/越权/注入 五类 | 0.8–1.2 M | 按**规则模板**合成（每类参数化生成），标签由构造过程给出（非人工主观判定） | 每类样本必须含"正确行为"字段（拒答/指出缺失项/指出矛盾），且负例（不该拒答的正常请求）占 ≥30%，防止模型学成"一问就拒" |
| S4 工艺参数推理 | 公式链推理链（CoT） | 1.2–1.8 M | 全部**程序生成**：随机采样合法参数 → 用公式算出结果 → 生成中间步骤文本。答案由计算给出，不经模型手写 | 生成器自带一次独立复算校验；参数域必须在物理合法区间（ap>0、D>0 等）；困难层要求 ≥3 步链 |
| S5 多模态（受限） | 合成图纸图 + 真值 | ≤0.5 M | 只能用 `scripts/make_multimodal_images.py` 这类**确定性合成图**；真值由生成脚本落 `ground_truth.json` | 判决见 §2.3——**不要在云端微调 8B 文本模型来做视觉** |

### 2.3 可行性判决矩阵（先判决，再实现）

| 需求 | 判决 | 依据 |
|---|---|---|
| 单卡 LoRA 继续训练 8B（bf16, r≤32, seq≤2304） | **可交付** | 实测 288 steps / 2 epochs / 58.5 min / ~1662 tok/s / 峰值 28.3 GB < 45 GB |
| 8B 全参微调 | **不可交付** | 45 GiB 单卡放不下（优化器状态 + 梯度即超），历史文档亦已判负 |
| QLoRA 4-bit 单卡训练 | **受限** | 4-bit 训练在本仓库未跑通实测记录；仅在 S3/S4 小数据微调时作为降成本备选 |
| 多机/多卡并行（TP/PP/DP 128 卡） | **不可交付** | 实例为单卡、无 RDMA；`virtu_omni/configs/train_3d_parallel.yaml` 属立项设计口径，不得作为执行依据 |
| 视觉能力训练（让 Virtu 自己看图） | **不可交付（本代）** | 现权重 `Qwen3ForCausalLM` 无视觉编码器；线上多模态由独立视觉通道（Qwen3-VL）承担。改造需换架构+对齐训练，超出单卡预算 |
| 云端直接产出可部署 GGUF | **不可交付** | 云端实例磁盘仅 ~100 GB 空闲，合并+量化产物超限；约定为"云端只出 adapter（≤350 MB），合并/量化/GGUF 一律本地做" |

## 3. 超参数配置策略

### 3.1 基线配置（默认执行值，全部来自本仓库实测可用组合）

```yaml
# 云端：单卡 L40S 45GiB，bf16 LoRA
base_model: /root/public-storage/model/Qwen/Qwen3-8B     # 已在盘上（16 GB, 5 shards），禁止重复下载
precision: bf16
attention: sdpa                    # flash-attn 在本镜像装不上（无预编译轮、源码编译 0% CPU 挂死）
gradient_checkpointing: true
max_seq_length: 2304
batch_size: 2
gradient_accumulation_steps: 8     # 有效 batch = 16
group_by_length: true
learning_rate: 1.0e-4
scheduler: cosine
warmup_steps: 15
weight_decay: 0.0
lora:
  r: 32
  alpha: 64                        # scaling = alpha/r = 2.0
  target_modules: [q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj]
  dropout: 0.05
epochs: 2
checkpoint: 按 step（每 100 step）+ 原子写 + 保留最近 3 个
```

### 3.2 分 Stage 偏差（只列与基线不同处）

| Stage | lr | r/α | epochs | 有效 batch | 说明 |
|---|---|---|---|---|---|
| S1 领域知识 | 1e-4 | 32/64 | 2 | 16 | 基线照跑 |
| S2 工具编排 | 7e-5 | 32/64 | 3 | 16 | JSON 输出要稳，降 lr 抑过拟合；早停看**schema 合法率**而非只看 loss |
| S3 边界安全 | 5e-5 | 16/32 | 2 | 32（4×acc8） | 数据量小、易把"整体话风"训坏（过度拒答），故低 lr + 小 r + 大 batch |
| S4 参数推理 | 1e-4 | 32/64 | 2 | 16 | 与 S1 同参；链长决定 seq，必要时 max_len 提到 3072 并 batch 降到 1 |

### 3.3 为什么不用"更大 batch / 更长 seq"

实测过：**WDDM 桌面 GPU 上 bs>16 是吞吐悬崖**（本地）；云端 sdpa 下 attention 激活按 O(s²) 增长，
把 batch 从 2 提到 4 会让 28.3 GB 峰值顶到 45 GB 边缘并触发重计算抖动。
所以调参优先动 lr / r / epochs，**不动 batch × seq 的乘积**。

### 3.4 三个"必须自检"的坑（历史已踩）

1. **loss 在掉不等于在学**：`virtu_omni/training/trainer.py:126` 在模型不返回 loss 时静默填 `torch.tensor(0.0)`。
   本案要求：训练脚本每 10 step 断言 `loss > 0 且 finite`，并把 `lr / tok_per_s / grad_norm` 一并写进 receipt，供事后回算。
2. **门控必须验产物**：跑前 `rm -f` 产物、跑后校验行数与字段齐备（历史上残缺的 1 行 json 曾骗出假 ARTIFACT_OK）。
3. **别拿被污染的时延解步数**：计时腿是独占资源，起第二条链前必须先用进程表证明第一条已退出；跨会话共享 Ollama/桥服务时先重列实例。

### 4.1 阶段间依赖与"失败重跑"规则

- 每个 Stage 从**上一个已验收通过的适配器**继续训（而非从损坏的合并件继续），并保留 `base + adapter_chain` 谱系记录。
- 单 Stage 不达标：先按 `not_retrieved`（数据里根本没有该知识）/ `not_expressed`（数据有但模型没学会）/ `schema-fail`（输出格式崩）分流——
  - `not_retrieved` → 补数据、不补超参；
  - `not_expressed` → 加 epoch/提 lr，数据不动；
  - `schema-fail` → 先修序列化与 eos/pad 配置，再谈训练。
  最多重跑 3 轮，3 轮不过则升级为设计问题（回到 §0/§2 重判），不得无限调学习率。

## 5. 资源调度优化方案

1. **单卡串行 + 队列化**：所有云端任务排队跑，禁止在同一实例并发两个"训练+评测"计时腿（历史上并发两条链同时毁掉训练与 p95 统计）。
2. **长链分段 + 断点续训**：每 100 step 落 checkpoint（原子写：临时名 + rename + 校验和），链脚本支持从 `resume_from` 继续；评测 runner 已实现按 `case_id` 去重续跑（append-only `raw.jsonl`）。
3. **云端只出 adapter，本地产合并/量化**：adapter ≈ 350 MB，可 SFTP 回传；16 GB 合并与 GGUF 量化放本地，避免云端 100 GB 磁盘被 checkpoint 吃满。
4. **数据驻留策略**：`/root/public-storage` 只读挂基座；训练语料上传一次、按 `dataset_sha256` 命名缓存，禁止每轮重新下载（历史上明确"基座已在盘上，不要重复下载"）。
5. **网络与包管理**：实例上 pip 走直连 PyPI（ tuna/aliyun 镜像在本机 TLS handshake EOF，实测只有 `pypi.org` 通）；训练网不存在 ⇒ 不做分布式。
6. **实例口令管理**：`DAMODEL_HOST/PORT/USER/PASS` 全部走环境变量或本地文件（`.damodel_pass`，跑完即删）；
   **仓库内多处脚本硬编码了回退口令且该口令已进 git 历史**（`damodel_ssh_runner.py:12` 等 5 处）⇒ P0 期内轮换并删除硬编码，改 `ssh_config`/key 登录。
7. **监控**：训练期每 5 min 采 `nvidia-smi` 显存/util 写日志；显存峰值连续 3 次超 40 GB 即自动降 batch 重排（避免 OOM 把整条链打死）。

## 6. 效果验证节点（每阶段都有卡口）

| 节点 | 时机 | 手段 | 通过标准 |

| V0 管线自检 | 每 Stage 启动前 5 min | tiny cuda+bf16 冒烟跑遍每个臂（1 个 batch, 10 step） | loss 有限且下降、显存峰值 <40 GB、产物落盘可读 |

| V4 部署一致性 | S5/S6 | 线上 `/v1/chat/completions` 采样 10 条 → 与本地同权重推理逐条比对 | 线上响应与 receipt 指纹一致；云失败时返回 503 而非模板 |

**发布阻断条件（任一即不得发布）**：`transport_error` >5%；`raw.jsonl` 行数 < 计划用例数；任一维度得分为 0 且原因是判分器异常（`grader_error`）；训练 receipt 缺失 `dataset_sha256`。
