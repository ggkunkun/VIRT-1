## 2. Phase 1：¥0，修掉让训练"不粘"的三个数据缺陷

这三项都在本地 CPU 上做，且是**性价比最高的质量来源**——因为它们决定下一轮训练能不能生效：

1. **工具 schema 用 SSOT 重生成**（`VIRTU_CAPABILITY_REPORT.md` 根因 B 实测：语料教 8 个名字，调度端收 10 个**完全不同**的名字，字面重叠 0 ⇒ "学得完美也会被拒 100%"）。改 `scripts/build_toolcall_corpus.py` 直接从 `cadcam_toolchain_manifest.json` 读定义，禁止手写别名。运行时 `legacy_aliases` 兼容层保留，但**语料里不得再出现旧名**。
2. **数值不靠权重学，靠工具算**。实测 5/5 在服产物算 `n=1000·Vc/(π·D)` 全错，而现有守卫只覆盖主轴转速一条公式（他人已修，本轮实测验证：241.67/1000/382/7639 全部被改写为 2387.3）。把这类题**一律教成 tool call**（`cadcam_*` 里已有 preflight/dispatch 路径），比用 1.5M token 去把算术烙进权重便宜且精确。
3. **每条 gold 必须机器可判满分 + 防泄漏**。沿用已有 `virtu_eval/validate_cases.py`、`contamination_check.py`、`holdout_check.py`（实测 SFT 冒烟：`dropped_eval_overlap=12, contaminated=0`）。这条闸门不加钱，但没它就会有"训练集记住评测集"的假增益——上一轮 0.7292 的尺寸保真率 vs 94.44% 关键词通过率，差距就出在这里。

## 8. ¥0 前置的两条实测结论（2026-11-01 17:1x）

### 8.1 根因 B 在真服务链路上已闭合

对 live `127.0.0.1:8000` 直接投 4 个 CAD/CAM 任务（带 `cadcam_toolchain_manifest.json` 的 10 条真实 schema，`auto_execute` 关闭以免触碰物理 CAD）：

| 任务 | 吐出的工具名 | 调度器是否认识 |
|---|---|---|
| SOLIDWORKS 参数化法兰 | `cadcam_solidworks_model` | ✅ |
| NX 改凸台高度 | `cadcam_nx_journal` | ✅ |
| CIMCO 宏程序校验 | `cadcam_cimco_validate` | ✅ |
| VERICUT 仿真 | `cadcam_vericut_simulate` | ✅（修截断后，见 8.2） |

⇒ 语料当年教的是 8 个旧名、调度器收 10 个新名（字面重叠 0），但**运行时别名层 + `virtu-toolcall` 专家把这条断裂在部署侧接上了**。所以 §2 的"语料按 SSOT 重生成"仍值得做（去掉兼容层的维护债），但它**不再是"训练能不能生效"的先决条件**，也不该再拿它当不训练的借口。

### 8.2 新修缺陷：小 token 预算会把工具调用整枪打死

实测 `max_tokens=220` 时模型选对了工具，但 arguments 被截成半截 JSON，llama-server 直接回 500，桥原样透传：
`Ollama API HTTP 500: invalid tool call arguments for "cadcam_vericut_simulate": unexpected end of JSON input`。
同一请求 700/1024 即正常。已在 `virtu_real_backend._chat_with_room()` 修：命中该错误时放宽预算（`max(3×, 768)`）**只重试一次**，其他错误一律不重试直接抛（负例有测试兜底）。测试 `tests/test_tool_call_retry.py`（5 例 0.64 s，含"不许重试风暴"与"两处调用点都必须走包装"）；实链路 `scratch/check_tool_retry.py` 打印 `TOOL_TRUNCATION_RETRY_OK`。

**对训练/评测口径的连带影响**：`arms.json` 里 hf 臂 `max_tokens_cap: 256`、以及按 tier 收紧的 token 上限，正是此前 boundary 维 5/6 例判成 `partial_truncated` 的同源原因。**测评必须在够用的预算上跑**，否则测的是截断不是能力。

### 8.3 一条以前没人量的成本事实

一次工具轮光 schema 就 **`prompt_tokens = 2333`**（实测 usage）。这与 `TRAIN_ACCELERATION.md` 量的"tools schema 占语料 50.5% token"是同一件事的两端：**10 条工具定义的描述太长**。精简 schema（去营销话术、保留参数与单位）同时降推理首字延迟（本机该模型 17% GPU/83% CPU 分层，prefill 是瓶颈）与训练 token 单价，且 ¥0。
