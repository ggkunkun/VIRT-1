## 2. 先分层定性：是程序错、装夹错，还是模型错

遇到 VERICUT 碰撞/过切时，按下面顺序判定，避免“一碰撞就改程序”或“一碰撞就关碰撞检测”：

| 判定项 | 程序错 | 装夹/夹具错 | 机床模型偏置错 |
|---|---|---|---|
| 碰撞对象 | 刀具/刀柄 vs 零件、毛坯 | 刀具/刀柄 vs 夹具、卡爪、压板 | 组件之间（主轴、转台、尾座、刀塔） |
| NC 坐标 | 超出图纸/工艺安全值，或 G0 直接扎料 | 坐标符合图纸，但夹具包络侵入刀路 | NC 与夹具都正确，组件零点与机床图不符 |
| 典型证据 | 快速进给去除材料、F 为零 | 同一程序在正确夹具上不碰撞 | 组件 `Position` 与讲义/机床图不一致 |
| 修复位置 | CAM/NC 源文件 | 夹具模型/装夹位置/工件零点 | `.mch` 组件 `Position` |

**硬约束**：不得用“关闭机床碰撞检查”或“忽略错误”作为修复；修复后必须用同一工程重跑并留下前后日志。

## 3. NC 程序错误专项

### 3.1 `lathe_session_day1`（3 条错误）

**实测日志**

```text
错误:在 23 行:N1100 Z-1.81 ,刀具 "1" 碰撞 "Jaws"
错误:在 24 行:N1110 X2.32 ,刀具 "1" 碰撞 "Jaws"
错误:在 47 行:N0220 X.04,组件"Tool_1"上的刀具"1"快速进给去除材料,去除体积0.0011
```

**NC 上下文**（`lathe_program.mcd`）

```text
N1070 G1 Z-.795
N1080 X1.977
N1090 X2.16 Z-.9536
N1100 Z-1.81          ← 碰撞 Jaws
N1110 X2.32           ← 继续碰撞
...
N0210 G0 Z.16
N0220 X.04            ← G0 横向扎入毛坯
N0230 G1 Z.08 F10.
```

**根因分析**

1. 第 23/24 行：刀具 1 在 X2.16 的状态下把 Z 下到 -1.81，进入卡爪（Jaws）包络；随后 X 到 2.32，仍处于包络内。
   - 可能是零件在卡盘中的伸出长度不足，或卡爪模型位置比实际靠前；
   - 也可能是程序 Z 深度超过图纸卡爪让位区。
2. 第 47 行：`G0 Z.16` 后直接 `X.04`，快移横穿端面毛坯，属于**程序策略错误**，不是模型问题。

**修复建议（按优先级）**

| 优先级 | 动作 | 说明 |
|---|---|---|
| P1 | 把 N1100 的 Z 下刀改成“先退 X 到卡爪内径之外，再下 Z，再进 X” | 示例结构：`G0 X<SAFE_X>`（按夹具实测）→ `G0 Z-1.81` → `G1 X2.16 F...` → `N1110 X2.32`。`<SAFE_X>` 必须大于卡爪内径，不得照抄 |
| P1 | 若图纸要求必须切到 Z-1.81，复核零件伸出长度与卡爪位置 | 调整卡爪后移/零件多伸出，重新对 G54；不建议直接把 Z 改浅导致零件长度超差 |
| P1 | 第 47 行 `N0220 X.04` 改为 `G1 X.04 F...`，或先 `G0 Z.25` 再 `X.04` 再下 Z | 任何在毛坯端面下方的横向移动都必须是进给，不能是 G0 |
| P2 | 在 CAM 中给卡爪让位区加检查几何 | 让后处理前就发现 Z 进入卡爪 |

**验收标准**

- 重跑同一工程，日志不再出现 `23 行/24 行` 与 `Jaws` 碰撞；
- 不再出现“快速进给去除材料”；
- `错误数: 0`（警告可保留，但需逐条说明）。

### 3.2 `mill_session_day1`（2 组错误）

**实测日志**

```text
错误:在 280 行:N201 X4.125 Y2.00 Z1.07,组件"Tool"上刀具"9"的刀柄"Holder1""与"Fixture"碰撞
错误:在 281 行:N202 G28 G91 Z0,组件"Tool"上刀具"9"的刀柄"Holder1""与"Fixture"碰撞
错误:在 363 行:N266 G81 G99 X-2. Y6.5 Z1.433 R3.85 F10.,刀具 "7" 刀柄"Holder1" 碰撞 "Stock"
```

**NC 上下文**（`mill_program.mcd`）

```text
N200 G03 I-0.5631 J0.2712
N201 G00 Z3.6
N201 X3.00
N201 X4.125 Y2.00 Z1.07   ← 刀柄 Holder1 与 Fixture 碰撞
N202 G28 G91 Z0           ← 回零过程中继续碰撞
...
N263 G00 X-2. Y6.5B270.
N264 G43 Z15. H07 M08
N265 Z3.85
N266 G81 G99 X-2. Y6.5 Z1.433 R3.85 F10.   ← 刀柄与 Stock 碰撞
```

**根因分析**

1. 刀具 9（ENDMILL）的 Holder1 在 TLS 中直径为 1.375–1.9375 in（刀具直径 0.5 in），在 Z1.07 处已进入 Fixture 包络；同时 spindle 也与 Fixture 相交。说明**刀柄/主轴在夹具上方没有安全间隙**，或夹具模型高于实际。
2. `N202 G28 G91 Z0` 在刀柄仍处于夹具包络时回机床零点，会把碰撞拖到回零过程。回零前必须先退到安全 Z。
3. 刀具 7（DRILL）在 `G81 ... R3.85 Z1.433` 时刀柄与 Stock 相交 0.8176 in³，说明 R 平面/钻尖长度不足以让刀柄避开毛坯，属于**刀具长度或 R 平面设置错误**，不是夹具碰撞。

**修复建议**

| 优先级 | 动作 | 说明 |
|---|---|---|
| P1 | 把 N201 的 XY 定位与 Z 下刀拆开：先在 `Z3.6` 完成 `X4.125 Y2.00`，再单独 `G1 Z1.07` | 避免斜向快移同时进入夹具；Z 下刀用进给 |
| P1 | 回零前先退到安全 Z：`G0 Z<SAFE_Z>`（高于夹具顶面）再 `G28 G91 Z0` | 不允许在夹具包络内回零 |
| P1 | 刀具 9 改用更长刀具或更短刀柄，使 Z1.07 时 Holder1 底面高于 Fixture 顶面 | 改刀具后必须更新 `mill_tools.tls` 并重新对刀 |
| P2 | 刀具 7 加长钻头或提高 R 平面，保证刀柄最低点在 Stock 顶面之上 | 复核 `R3.85` 与毛坯顶面；必要时减小钻深/分段排屑 |
| P2 | 夹具模型位置用 X-Caliper 实测复核 | 若夹具模型比实际高，修正模型而不是改程序 |

**验收标准**

- 日志不再出现 `Holder1` + `Fixture` / `Stock`；
- 第 280/281 行与第 363 行无碰撞；
- `错误数: 0`，并保留修复前/后两份日志。

### 3.3 `millturn_session_day1`（4 类错误）

**实测日志**

```text
错误:在 66 行:Z.0313,组件"Tool"上的刀具"7901"快速进给去除材料,去除体积0.0112
错误:在 68 行:G1 X3.1992 Z-.0394 F..005,有进给速度的运动设定为零
错误:在 69/70/71 行,有进给速度的运动设定为零
错误:在 165 行:G1 A0. F20.,"Tool CUTTER"和"Sub_Fixture"碰撞
错误:在 165 行:G1 A0. F20.,"Tool HOLDER"和"Sub_Fixture"碰撞
错误:在 171 行:G0 Y0. Z-1.05,"Tool CUTTER"和"Sub_Fixture"碰撞
```

**NC 上下文**（`millturn_program.tap`）

```text
63: G0 Y0. Z2.223
64: X3.058
65: Z.223
66: Z.0313                 ← G0 快速进给去除材料
67: G99
68: G1 X3.1992 Z-.0394 F..005   ← F..005 非法，被解析为 0
...
162: G0 A1.5
163: M211
164: M251
165: G1 A0. F20.           ← A 轴旋转时 Tool CUTTER/HOLDER 与 Sub_Fixture 碰撞
...
171: G0 Y0. Z-1.05         ← 快移进入 Sub_Fixture
```

**根因分析**

1. **第 66 行**：`Z.0313` 是 G0 快移，直接扎入端面余量。属于程序策略错误。
2. **第 68 行**：`F..005` 是明显笔误（两个小数点），控制解析为 0，导致 68–71 行全部“进给为零”。这是**NC 语法/后处理错误**。
3. **第 165 行**：A 轴从 1.5 旋转到 0 时，刀具/刀柄与副主轴夹具 `Sub_Fixture` 相交。旋转轴动作前没有退到安全位置，或副主轴夹紧/松开状态不对。
4. **第 171 行**：`G0 Y0. Z-1.05` 快移进入 `Sub_Fixture`，缺少安全 Z 中间平面。

**修复建议**

| 优先级 | 动作 | 说明 |
|---|---|---|
| P0 | 第 68 行 `F..005` 改为合法进给（如 `F.005`，按 G99 in/rev 与图纸换算确认） | 这是确定的语法错误，必须先修 |
| P0 | 第 165 行 A 轴旋转前先退 X/Z 到安全平面，并确认 `M211/M251/M210` 的夹紧/松开顺序 | 旋转轴动作不得在副主轴夹具包络内进行 |
| P1 | 第 66 行 `Z.0313` 改为 `G1 Z.0313 F...`，或先到安全 Z 再下刀 | 端面余量必须进给切除 |
| P1 | 第 171 行 `G0 Y0. Z-1.05` 拆成“G0 到安全 Z → XY 定位 → G1 下 Z” | 避免快移进入副主轴夹具 |
| P2 | 在 CAM 中增加副主轴/下刀塔的碰撞检查几何 | 后处理前拦截 A 轴旋转碰撞 |

**验收标准**

- 第 66 行不再出现“快速进给去除材料”；
- 第 68–71 行不再出现“进给为零”；
- 第 165/171 行不再出现 `Sub_Fixture` 碰撞；
- `END-OF-FILE` 且 `错误数: 0`。

## 4. 机床模型偏置专项（103L / 103M / 103MT）

**实测状态**：三个工程的机床文件里，讲义点名的组件 `Position` 都是 0；讲义要求分别偏移 **32.25 in / 600 mm / 1972 mm**。

| 案例 | 机床文件 | 组件 | 当前 `Position` | 讲义要求 | 修复 |
|---|---|---|---|---|---|
| 103L | `lathe_session_103l_add_3d_models_to_the_machine.mch` | `Z`（Attach Base） | `X=0 Y=0 Z=0` | Z 零点距机床原点 **32.25 in** | 设 `Position Z=32.25`（`Unit="inch"`） |
| 103M | `mill_session_103m_add_3d_models_to_the_machine.mch` | `Z`（Attach X） | `X=0 Y=0 Z=0` | Z 零点距机床原点 **600 mm** | 设 `Position Z=600`（`Unit="millimeter"`） |
| 103MT | `millturn_session_103mt_add_3d_models_to_the_machine.mch` | `W`（Attach Base，Rotation I=180） | `X=0 Y=0 Z=0` | W 零点距机床原点 **1972 mm** | 设 `Position Z=1972`（`Unit="millimeter"`），并用 MDI 验证方向 |

**修复步骤（VERICUT 内）**

1. 打开对应 `.vcproject`，进入 **Machine/Control → 机床组件树**。
2. 选中讲义点名的组件（Z 或 W），在 **Configure Component → Position** 中填入上表数值。
3. 锁定模型（Lock Models），用 **MDI** 执行 `G0 Z0`（或 `G0 W0`）确认组件零点与机床图一致；注意 103MT 的 W 轴 `Rotation I=180`，方向必须实测确认。
4. 按 Session 104 设置碰撞表与行程限位；重新仿真，检查是否还有组件间碰撞。
5. 保存工程并记录修改前后坐标（用于回归）。

**不要在以下位置修**：

- 不要用“移动 NC 工件零点”去补偿组件偏置；
- 不要直接改 STL/PLY 模型坐标；
- 不要把 `Position` 填成负值来“看起来对齐”。

**验收标准**

- 组件 `Position` 与讲义数值一致（32.25 / 600 / 1972）；
- MDI 下 Z/W 零点与机床图一致；
- 重新仿真无组件间碰撞、无行程超限；
- 修改记录写入工程版本说明。

## 7. 预防措施

1. **CAM 侧**：把夹具、卡爪、副主轴、刀柄作为检查几何；所有端面/槽底横向移动使用 G1，禁止 G0 贴料。
2. **后处理侧**：对 `F..005` 这类非法小数点做后处理校验；对 G0 三轴联动下刀做静态检查。
3. **机床构建侧**：建立“导入模型 → Attach → 按机床图填 Position → Lock → MDI 验零点 → 碰撞表/行程 → 保存”的固定流程。
4. **回归侧**：每个修复案例保留“修复前/修复后”两份 VERICUT 日志，并把结论写回案例索引的 `reproduction` 字段。
