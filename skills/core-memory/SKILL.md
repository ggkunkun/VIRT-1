# 记忆、沉淀与技能结晶

> 只记长半衰期的东西；先查再问。

## memory.recall_before_ask — 先查再问

**何时适用**：用户引用历史，或任务可能已有既定约定。

**步骤**

1. 先查项目记忆与历史记录（本地日志 / 检索）。
2. 查到 → 直接沿用并说明来源；查不到 → 再问，且问具体选项而非开放问题。
3. 问到的新约定立即写回记忆文件。

**硬约束**

- 不得凭印象编造'上次你说过'。
- 记忆冲突时以用户当前表述为准，并更新记录。

**验收门**

- `G-MEM-RECALL`：引用历史时能指出具体文件/条目。
- 判失败：出现无出处的'你之前提到'。

**反例（真实踩过的坑）**

- 重复问用户已经回答过的偏好。
- 把别的项目的约定套到当前项目。

## memory.write_what_lasts — 只写长半衰期

**何时适用**：任务结束、或用户给出长期约定。

**步骤**

1. 判断半衰期：一次性结果（不写）/ 本周有效（不写）/ 跨会话有效（写）。
2. 写'约束与结论'，不写'过程流水'。
3. 带日期与触发条件，便于日后判断是否过期。
4. 同一主题合并更新，不追加重复条目。

**硬约束**

- 禁止把搜索结果、临时路径、报错原文写进长期记忆。
- 禁止记录密钥与个人隐私。

**验收门**

- `G-MEM-WRITE`：每条记忆都能回答'下次什么情况下会用到'。
- 判失败：记忆里出现一次性日志或可复现的命令输出。

**反例（真实踩过的坑）**

- 把 300 行构建日志写进记忆。
- 同一偏好写了五遍，互相矛盾。

## memory.crystallize_skill — 成功流程结晶为技能

**何时适用**：同一类任务已成功做过 2 次以上，或踩坑代价很高。

**步骤**

1. 抽取稳定部分：触发条件、步骤、硬约束、验收门、反例。
2. 写成 SKILL 格式（frontmatter + body），并绑定可调用工具。
3. 去掉一次性细节（具体文件名、临时端口）。
4. 加一条'何时不适用'。

**硬约束**

- 技能必须带 gate，否则无法判断是否执行到位。
- 不得把未验证的做法写成技能。

**验收门**

- `G-MEM-SKILL`：技能含 trigger/steps/rules/gate/failure_modes 五要素。
- 判失败：技能只有背景介绍没有可执行步骤。

**反例（真实踩过的坑）**

- 把一次成功的偶然操作固化成'最佳实践'。
- 技能写了 2000 字但没人能照着做。

## 输出契约

执行本族任一原子后，输出必须包含：所用原子 id、实际执行的检查、检查的原始输出（或摘要）、
以及 `measured` / `asserted` / `insufficient` 三档证据等级。无证据不得写 `measured`。
