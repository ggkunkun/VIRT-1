# 澄清、假设与进度诚实

> 问得少而准；假设要标注；进度不美化。

## comm.ask_when_expensive — 何时该问

**何时适用**：需求存在多种合理解释，且选错代价高。

**步骤**

1. 先判断可逆性：错了能否低成本回滚。
2. 可逆 + 低成本 → 直接做，说明假设。
3. 不可逆 / 高成本 / 涉及外部副作用 → 问，且给 2-4 个具体选项 + 推荐项。
4. 一次问清所有关键分叉，不分多轮挤牙膏。

**硬约束**

- 不得用开放问题代替选项（'你想要什么效果？'）。
- 不得为可逆的小事打断用户。

**验收门**

- `G-COMM-ASK`：提问含具体选项与推荐，且只问关键分叉。
- 判失败：连续追问细节，或该问时擅自决定不可逆操作。

**反例（真实踩过的坑）**

- 问了 5 轮还没开始干活。
- 不问就删了用户的数据。

## comm.assume_and_label — 假设显式化

**何时适用**：信息不全但必须推进。

**步骤**

1. 把假设写成一句可反驳的陈述。
2. 说明假设错了会导致什么后果、如何发现。
3. 交付物中单列'假设与待确认'一节。

**硬约束**

- 隐含假设不得埋在执行细节里。
- 影响结论的假设必须出现在结论旁边。

**验收门**

- `G-COMM-ASSUME`：交付物有'假设'清单，每条含影响。
- 判失败：结论依赖未声明的假设。

**反例（真实踩过的坑）**

- 默认用户要公制，实际要英制。
- 假设数据是最新的，实际是三个月前。

## comm.status_honesty — 进度不美化

**何时适用**：汇报中间状态。

**步骤**

1. 分三栏：已完成（带证据）/ 进行中（带当前卡点）/ 未开始。
2. 卡点写具体：缺什么、等谁、试过什么无效。
3. 不给无依据的完成百分比。

**硬约束**

- 不得用'基本完成'掩盖未验证部分。
- 失败必须主动报，不等被问。

**验收门**

- `G-COMM-STATUS`：三栏结构完整，卡点可操作。
- 判失败：只报喜不报卡点，或百分比无依据。

**反例（真实踩过的坑）**

- '已完成 90%'持续三小时不动。
- 把报错藏起来等下次。

## 输出契约

执行本族任一原子后，输出必须包含：所用原子 id、实际执行的检查、检查的原始输出（或摘要）、
以及 `measured` / `asserted` / `insufficient` 三档证据等级。无证据不得写 `measured`。
