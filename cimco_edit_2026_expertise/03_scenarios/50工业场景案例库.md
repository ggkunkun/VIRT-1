## A 类　程序编辑与优化（SC-001 ~ SC-010，10 个）

### SC-001 混乱块号重编与规范化
- 场景类别 / 难度 / 适用控制系统：A 程序编辑与优化 / 初级 / FANUC、SIEMENS 通用
- **现场问题**：车间流传的法兰加工程序块号从 N10 跳到 N80 后又出现 N50、N55，段落间步长不一。操作工希望按固定步长（10）统一重排，便于对单与电话沟通定位行号。
- **输入样例**（块号混乱的真实片段）：
```
%
O1600 (FLANGE)
N10 G21 G40 G97 G99 G54
N30 T0101
N80 G97 S800 M03
N50 G00 X170.0 Z5.0
N55 G00 Z0.0
N60 G01 X-1.0 F0.2
N170 M05
N180 G28 U0.0 W0.0
N185 M30
%
```
- **诊断/分析**：官方 `program-tabs/nc-functions/blocknumbers/` 明确提供 `Renumber / Ctrl+T`：插入或重排块号；`Configure Block Numbering` 可设起始值与步长。问题属于块号外观层，不涉及 G 代码语义，重编不会改变刀路。
- **处理步骤**：
  1. 在 CIMCO Edit 中打开程序，确认当前 File Type 为对应系统方言（FANUC）。
  2. `NC Functions` 选项卡 → `Block Numbers` → `Renumber`（快捷键 `Ctrl+T`）。
  3. 设置 Start=10、Increment=10、Decimals=0；勾选"跳过注释/空行"（若对话框提供）。
  4. 勾选 `Result to new window` 先生成副本，核对无误后再覆盖原文件。
  5. 保存后运行静态校验确认未引入语法回归。
- **修复后代码/输出**（完整可复用）：
```
%
O1600 (FLANGE)
N10 G21 G40 G97 G99 G54
N20 T0101
N30 G97 S800 M03
N40 G00 X170.0 Z5.0
N50 G00 Z0.0
N60 G01 X-1.0 F0.2
N70 M05
N80 G28 U0.0 W0.0
N90 M30
%
```
- **验证方法**：`cimco_bridge.py::validate_fanuc_macro_b(code)` 返回 `is_valid=true, syntax_checked=true, errors=[]`（块号不影响判定）；另用官方 `Go to Line/Block Number / Ctrl+J` 抽查 N20/N90 是否连续。字段含义：`status=success` 表示哨兵已运行；`errors` 非空列出具体问题行。
- **能力边界**：无（纯编辑功能）。
- **证据来源**：https://docs.cimco.com/en/docs/edit/2026/program-tabs/nc-functions/blocknumbers/ ；https://docs.cimco.com/en/docs/edit/2026/editor-setup/file-types/block-numbers/

### SC-002 Transform 镜像加工对称轮廓
- 场景类别 / 难度 / 适用控制系统：A 程序编辑与优化 / 中级 / FANUC（铣削）
- **现场问题**：左右对称的板件轮廓，已编好右半侧刀路，需镜像生成左半侧。手工改 X 符号易漏改圆弧 I/J 与 G41/G42 补偿方向，导致过切。
- **输入样例**（右侧轮廓，G54，XY 平面）：
```
%
O2000 (RIGHT PROFILE)
G90 G54 G17 G40 G21
T01 M06
M03 S1800
G43 H01 Z50.0 M08
G00 X20.0 Y-5.0
G01 Z-4.0 F200.
G01 Y0.0 F300.
G01 X60.0 Y20.0
G03 X80.0 Y0.0 I20.0 J-20.0
G01 Z50.0 M09
M05
M30
%
```
- **诊断/分析**：官方 `nc-functions/transform/` 提供 `Mirror`（绕指定直线镜像）与 `Turning Program` 车削选项。镜像对象为"轮廓"，对话框按 X/Y/Z 指定镜像轴；对本例绕 Y 轴镜像使 X 取反，须人工复核圆弧方向由 G03↔G02 互换及刀补 G41↔G42 互换。
- **处理步骤**：
  1. 选中轮廓段（G00 X20… 至 G03…），或全选程序。
  2. `NC Functions` → `Transform` → `Mirror`。
  3. 选择绕 Y 轴镜像（X 取反）；确认 `Turning Program` 未勾选（铣削）。
  4. 勾选 `Result to new window` 生成新文档，不覆盖原程序。
  5. 在新窗口手工把 `G03` 改为 `G02`、若有 `G41` 改为 `G42`，并复核 `I` 符号（相对圆心约定）。
  6. 重新建立安全抬刀与收尾段。
- **修复后代码/输出**（镜像并修正圆弧方向后）：
```
%
O2001 (MIRRORED LEFT PROFILE)
G90 G54 G17 G40 G21
T01 M06
M03 S1800
G43 H01 Z50.0 M08
G00 X-20.0 Y-5.0
G01 Z-4.0 F200.
G01 Y0.0 F300.
G01 X-60.0 Y20.0
G02 X-80.0 Y0.0 I-20.0 J-20.0
G01 Z50.0 M09
M05
M30
%
```
- **验证方法**：`validate_gcode(code)` 返回 `is_valid=true, errors=[]`；再用 `Ctrl+Shift+P` 背绘叠加原/镜像两段，目视确认关于 Y 轴对称且无交叉扎料。字段 `errors` 中的 "No valid G-code words" 表示某行未被解析，须检查。
- **能力边界**：Transform 只做几何/数值变换，不自动改圆弧方向与刀补；G02/G03、G41/G42 必须由人确认。无 B-XX 冲突。
- **证据来源**：https://docs.cimco.com/en/docs/edit/2026/program-tabs/nc-functions/transform/

### SC-003 Transform 旋转阵列孔位
- 场景类别 / 难度 / 适用控制系统：A 程序编辑与优化 / 中级 / FANUC（铣削）
- **现场问题**：单孔程序需绕原点旋转复制成 4 孔阵列。手工算 COS/SIN 易错，希望用 Rotation 对话框按 90° 步进生成。
- **输入样例**（单孔，绝对坐标定位 + G81）：
```
%
O2010 (ONE HOLE)
G90 G54 G17 G21 G40 G80
T02 M06
M03 S1200
G43 H02 Z50.0 M08
G00 X50.0 Y0.0
G81 Z-12.0 R2.0 F120
G80
G00 Z50.0 M09
M05
M30
%
```
- **诊断/分析**：`nc-functions/transform/` 的 `Rotate` 支持"绕指定点、指定角度"旋转轮廓，参数 `Point (X,Y)` 与 `Angle`，并可设 `Arc type`（Auto detect / Relative to start 等）。适合把已有点位绕 (0,0) 复制旋转。
- **处理步骤**：
  1. 选中定位与循环段 `G00 X50.0 Y0.0` 至 `G80`。
  2. `NC Functions` → `Transform` → `Rotate`；`Point (X,Y)` 填 0,0；`Angle` 填 90。
  3. `Arc type` 保持 `Auto detect`；勾选 `Result to new window`。
  4. 重复操作生成 180°、270° 三份，或改用 FANUC Macro B（见 SC-012）更优。
  5. 合并 4 份到同一程序，保留一次 G80 与一套收尾。
- **修复后代码/输出**（4 孔阵列，等价于旋转 0/90/180/270）：
```
%
O2011 (4-HOLE ROTARY ARRAY)
G90 G54 G17 G21 G40 G80
T02 M06
M03 S1200
G43 H02 Z50.0 M08
G00 X50.0 Y0.0
G81 Z-12.0 R2.0 F120
G00 X0.0 Y50.0
G00 X-50.0 Y0.0
G00 X0.0 Y-50.0
G80
G00 Z50.0 M09
M05
M30
%
```
- **验证方法**：`validate_fanuc_macro_b(code)` 的 `variables_count=0`、`errors=[]`、`status=success`；背绘核查 4 孔中心距原点均为 50.0 且均布 90°。
- **能力边界**：Rotate 变换是静态几何复制，非机床坐标系旋转（G68）；不要与 FANUC G68 坐标旋转混淆。无 B-XX 冲突。
- **证据来源**：https://docs.cimco.com/en/docs/edit/2026/program-tabs/nc-functions/transform/

### SC-004 Transform 平移整个轮廓到新坐标
- 场景类别 / 难度 / 适用控制系统：A 程序编辑与优化 / 初级 / FANUC、SIEMENS
- **现场问题**：工装改位后，整套轮廓需整体偏移 X+100、Y-30，且不允许逐行手改坐标。
- **输入样例**：
```
%
O2020 (ORIGINAL CONTOUR)
G90 G54 G17 G21
T01 M06
M03 S1500
G43 H01 Z50.0 M08
G00 X10.0 Y10.0
G01 Z-2.0 F150.
G01 X50.0 Y10.0
G01 X50.0 Y40.0
G01 X10.0 Y40.0
G01 X10.0 Y10.0
G00 Z50.0 M09
M05
M30
%
```
- **诊断/分析**：`Transform → Translate` 提供 `Translate (X,Y,Z)` 输入偏移值，支持 `Arc type` 四种约定。整体平移不改变圆弧半径与形状，安全、可逆。
- **处理步骤**：
  1. 全选程序（或仅选轮廓段）。
  2. `NC Functions` → `Transform` → `Translate`。
  3. 填 `Translate (X,Y,Z)` = 100, -30, 0；`Arc type` 用 `Auto detect`。
  4. 勾选 `Result to new window`，核对新坐标。
  5. 保存为 O2021 并留原程序备份。
- **修复后代码/输出**：
```
%
O2021 (SHIFTED CONTOUR +100/-30)
G90 G54 G17 G21
T01 M06
M03 S1500
G43 H01 Z50.0 M08
G00 X110.0 Y-20.0
G01 Z-2.0 F150.
G01 X150.0 Y-20.0
G01 X150.0 Y10.0
G01 X110.0 Y10.0
G01 X110.0 Y-20.0
G00 Z50.0 M09
M05
M30
%
```
- **验证方法**：`validate_gcode(code)` → `is_valid=true, errors=[]`；用 `Ctrl+J` 跳到 X110.0 行核对；背绘对比两版轮廓形状一致、仅位置平移。
- **能力边界**：无（官方 Transform 原生功能）。
- **证据来源**：https://docs.cimco.com/en/docs/edit/2026/program-tabs/nc-functions/transform/

### SC-005 批量查找替换换刀具号与进给
- 场景类别 / 难度 / 适用控制系统：A 程序编辑与优化 / 初级 / 全系统
- **现场问题**：刀具表调整，原 T0101（Φ10 立铣刀）统一换为 T0303，且所有 F300. 提至 F360.。逐处手改费时且易漏。
- **输入样例**：
```
%
O2030 (BATCH REPLACE DEMO)
G90 G54 G17 G21 G40
T0101
M03 S2000
G43 H01 Z50.0 M08
G00 X0.0 Y0.0
G01 Z-3.0 F300.
G01 X40.0 F300.
G01 Y30.0 F300.
G00 Z50.0 M09
M05
M30
%
```
- **诊断/分析**：官方 `program-tabs/editor/find/` 提供 `Replace / Ctrl+H`，含 `Replace with`、`Replace in selection only`、`Replace All from File`（从外部文件导入多条 find/replace 对，每行一对）、`Create a new, duplicate document`。适合批量替换。
- **处理步骤**：
  1. `Ctrl+H` 打开 Replace；`Find what` 填 `T0101`，`Replace with` 填 `T0303`，`Replace All`。
  2. 第二次：Find `F300.` → Replace `F360.`，`Replace All`。
  3. 若替换对很多，建外部文本两列（左旧右新），用 `Replace All from File` 一次导入。
  4. 勾选创建副本文档，确认无误后保存。
  5. 复核 `G43 H01` 是否需同步改 `H03`（刀补号随刀具变化，须人工判断）。
- **修复后代码/输出**：
```
%
O2030 (BATCH REPLACE DEMO)
G90 G54 G17 G21 G40
T0303
M03 S2000
G43 H03 Z50.0 M08
G00 X0.0 Y0.0
G01 Z-3.0 F360.
G01 X40.0 F360.
G01 Y30.0 F360.
G00 Z50.0 M09
M05
M30
%
```
- **验证方法**：`validate_gcode(code)` → `errors=[]`；`Ctrl+F` 搜索旧值 `T0101`、`F300.` 应 0 命中；搜索 `T0303` 命中 1、`F360.` 命中 3。
- **能力边界**：替换是纯文本操作，不校验刀补号 H/D 与刀具号的匹配，须人工核对。无 B-XX 冲突。
- **证据来源**：https://docs.cimco.com/en/docs/edit/2026/program-tabs/editor/find/

### SC-006 注释清理与"##"转义防误判
- 场景类别 / 难度 / 适用控制系统：A 程序编辑与优化 / 中级 / FANUC（含 Macro B）
- **现场问题**：程序里夹杂大量调试注释与空行，其中一行以 `#100=...` 开头被宏模板误当作块号占位；需清理注释但保留合法宏变量。
- **输入样例**：
```
%
O2040 (COMMENT CLEANUP)
(DEBUG 2026-10-01 REMOVE LATER)
G90 G54 G21
(OLD TOOL T0101 - SUPERSEDED)
#101=50.0 (SAFE Z)
G00 X0.0 Y0.0
( TEMP NOTE )
G01 X#101 F200.
G00 Z50.0
M05
M30
%
```
- **诊断/分析**：官方 `nc-functions/scripts/writing-scripts/` 说明：宏插入时行首 `#` 会被当作块号占位并替换为块号值；若要在字符串行首输出字面 `#`（如 Fanuc Macro B 变量），应写 `##`。清理注释时须避免把合法 `#101` 破坏。
- **处理步骤**：
  1. 用 Find/Replace 正则或脚本删除 `(DEBUG ...)`、`(OLD TOOL ...)`、`( TEMP NOTE )` 等纯调试注释（官方支持 Regular Expressions，见 `editor-setup/regex/`）。
  2. 保留 `(SAFE Z)` 等有工艺意义的注释。
  3. 检查是否存在行首裸 `#`：在宏模板中应写 `##` 才能输出字面 `#`；在已生成的 NC 中 `#101` 本身合法，不需转义。
  4. 重排空行，使每段刀具/工步间保留一个分隔空行。
  5. 保存并静态校验。
- **修复后代码/输出**：
```
%
O2040 (COMMENT CLEANUP)
G90 G54 G21
#101=50.0 (SAFE Z)
G00 X0.0 Y0.0
G01 X#101 F200.
G00 Z50.0
M05
M30
%
```
- **验证方法**：`validate_fanuc_macro_b(code)` → `variables_count=1, variables=["#101"], errors=[], status=success, syntax_checked=true`。若把 `#101` 误删，`variables_count` 会变成 0，可立即发现。
- **能力边界**：无（编辑+宏插入语法规则来自官方）。
- **证据来源**：https://docs.cimco.com/en/docs/edit/2026/program-tabs/nc-functions/scripts/writing-scripts/ ；https://docs.cimco.com/en/docs/edit/2026/regex/

### SC-007 多段程序合并为单一主程序
- 场景类别 / 难度 / 适用控制系统：A 程序编辑与优化 / 中级 / FANUC
- **现场问题**：粗加工、精加工分为两个文件，现场希望合并成一个程序一次装夹跑完，同时只能保留一个 `%`、一个 `O` 号、一个 `M30`。
- **输入样例**（两个文件片段）：
```
%                         %
O2050 (ROUGH)             O2051 (FINISH)
G90 G54 G21               G90 G54 G21
T0101                     T0202
M03 S800                  M03 S1200
G00 X100.0 Z2.0           G00 X80.0 Z2.0
G01 Z-20.0 F0.2           G01 Z-20.0 F0.1
G00 X120.0 Z50.0          G00 X120.0 Z50.0
M05                       M05
M30                       M30
%                         %
```
- **诊断/分析**：合并属文本层操作；风险在于重复的 `%`、`O`、`M30` 会让解析器提前结束程序，以及 program-end 判定只认最后一个 M30。应删除第一段的 `%`/`O`/`M30` 与第二段的 `%`/`O`，保留中间 M05/M03 换刀逻辑。
- **处理步骤**：
  1. 打开两文件，复制第二段正文（不含首尾 `%` 和 `O` 行）。
  2. 粘贴到第一段 `M30` 之前，删除第一段的 `M30`。
  3. 保留第二段 `T0202` 与 `M03 S1200`，并在换刀前插入 `M05` 确保主轴停。
  4. 确认全文仅 1 个 `%` 起止对、1 个 `O` 号、1 个 `M30`。
  5. 静态校验收尾。
- **修复后代码/输出**：
```
%
O2050 (ROUGH+FINISH COMBINED)
G90 G54 G21
T0101
M03 S800
G00 X100.0 Z2.0
G01 Z-20.0 F0.2
G00 X120.0 Z50.0
M05
T0202
M03 S1200
G00 X80.0 Z2.0
G01 Z-20.0 F0.1
G00 X120.0 Z50.0
M05
M30
%
```
- **验证方法**：`validate_fanuc_macro_b(code)` → `errors=[]`（若残留两个 M30 不会报错，但 `%` 重复可能导致语法哨兵报 "No valid G-code words"）；人工计数 `%`=2、`O`=1、`M30`=1。
- **能力边界**：合并不改变刀路，也不做工艺合理性判断；换刀点安全性须人工/背绘确认。无 B-XX 冲突。
- **证据来源**：https://docs.cimco.com/en/docs/edit/2026/program-tabs/nc-functions/insert-remove/

### SC-008 按工步拆分主程序
- 场景类别 / 难度 / 适用控制系统：A 程序编辑与优化 / 中级 / FANUC
- **现场问题**：一个长程序含 3 把刀，需按刀具拆成 3 个独立文件便于分段调试与外发。
- **输入样例**：
```
%
O2060 (3-TOOL JOB)
G90 G54 G21
T0101
M03 S800
G00 X100.0 Z2.0
G01 Z-20.0 F0.2
M05
T0202
M03 S1000
G00 X80.0 Z2.0
G01 Z-15.0 F0.15
M05
T0303
M03 S1200
G00 X60.0 Z2.0
G01 Z-10.0 F0.1
M05
M30
%
```
- **诊断/分析**：`Insert/Remove` 支持按范围选择/删除（从换刀、进给或主轴值到下一个的范围）。拆分核心是给每段补齐 `%`/`O`/`M30` 与安全起点。
- **处理步骤**：
  1. 定位每个 `T` 换刀行作为分段边界。
  2. 复制第 1 段到新文件，补 `%` + `O2061` + 原有收尾 `M05`，末尾加 `M30` + `%`。
  3. 同法生成 O2062（T0202）、O2063（T0303）。

### SC-012 FANUC WHILE/DO/END 分层循环
- 场景类别 / 难度 / 适用控制系统：B 控制系统适配 / 高级 / FANUC Macro B
- **现场问题**：把整块铝件分 10 层铣到 Z-20，每层 2 mm，用 WHILE 循环自动下刀并限位保护（防止过切到 Z-20 以下）。
- **输入样例**（真实分层铣削宏）：
```
%
O2200 (LAYER MILL)
G90 G54 G17 G40 G49 G80 G21
T01 M06
M03 S2400
G43 H01 Z50.0 M08
#102=-20.00 (TARGET_Z)
#103=2.00 (AP_STEP)
#104=0.0 (CURRENT_Z)
G00 X0.0 Y0.0
G00 Z5.0
WHILE [#104 GT #102] DO1
  #104 = #104 - #103
  IF [#104 LT #102] THEN #104 = #102
  G01 Z#104 F180.
  G01 X400.0 F650.
  G01 Y300.0
  G01 X0.0
  G01 Y0.0
END1
G00 Z50.0 M09
G91 G28 Z0.
M05
M30
%
```
- **诊断/分析**：桥接器用正则 `WHILE\s*\[.*\]\s*DO\s*(\d+)` 识别循环、`END\s*(\d+)` 配对；不配对会报 `Unclosed WHILE DO` / `END without matching` / `Mismatched END`（均列为 critical，`is_valid=false`）。`IF [...] THEN #104 = #102` 做限幅，保证最后一层精确停在目标深度。
- **处理步骤**：
  1. 定义 `#104` 初始为 0（当前 Z），`#102` 为目标深度 -20，`#103` 为层深 2。
  2. `WHILE [#104 GT #102] DO1` 开始循环；编号 1~3 为 FANUC 允许的 DO 号。
  3. 循环内先递减 Z，再用 `IF` 限幅，然后下刀与横向走刀。
  4. 用 `END1` 闭合，编号与 DO 一致。
  5. 循环外抬刀、`G91 G28 Z0.`、`M05`、`M30`。
- **修复后代码/输出**：上例即完整可复用程序，校验 `variables_count=3`（#102/#103/#104）。
- **验证方法**：`validate_fanuc_macro_b(code)` → `errors=[]`，特别确认无 "Unclosed WHILE DO 1." 与 "without matching"；`status=success, syntax_checked=true`。若把 `END1` 改成 `END2`，返回会含 `Mismatched END 2, expected END 1...`，`is_valid=false`。
- **能力边界**：静态配对检查，不验证循环次数与工艺安全（如首刀 Z5→Z-2 是否撞刀），须背绘确认。无 B-XX 冲突。

- 场景类别 / 难度 / 适用控制系统：D 故障排查 / 中级 / FANUC Macro B
- **现场问题**：WHILE 循环漏写 END，宏无法闭合，校验报 `Unclosed WHILE DO 1.`，`is_valid=false`。
- **输入样例**（错误程序）：
```

G90 G54 G21
#103=1
#104=6

- **诊断/分析**：桥接器（cimco_bridge.py:61-64,89-91）：`WHILE...DO1` 入栈 `loop_stack`，扫描结束若栈非空，报 `Line X: Unclosed WHILE DO 1.`，属 critical，`is_valid=false`。真实 FANUC 程序必须每个 DO 对应一个 END（同号）。

M05
M30
%

### SC-034 哨兵不可用 CHECK_UNAVAILABLE 的正确处置
- 场景类别 / 难度 / 适用控制系统：D 故障排查 / 高级 / 全系统
- **现场问题**：校验返回 `status=partial`、`syntax_checked=false`，errors 含 `CHECK_UNAVAILABLE: gcode syntax sentinel did not run: ...`。误把"未检查"当成"检查通过"会埋雷。
- **输入样例**（程序本身语法合法，但哨兵运行环境缺失）：
```
%
O4300 (SENTINEL UNAVAILABLE SCENARIO)
G90 G54 G21
T0101
M03 S1000
G00 X50.0 Z2.0
G01 Z-10.0 F0.2
G00 Z50.0
M05
M30
%
```
- **诊断/分析**：CAPABILITY_BOUNDARIES §三与 cimco_bridge.py:111-121：当 `virtu_omni.serving.gbnf_grammar.validate_gcode_syntax` 不可用时，捕获异常后 `syntax_checked=false`、`status=partial`，并把原因以 `CHECK_UNAVAILABLE` 前缀写入 errors；`is_valid = syntax_checked and not critical`，故此时 `is_valid=false`。**这是既有 bugfix 固化的诚实退路**。
- **处理步骤**：
  1. 读 `status`：若为 `partial`，立即判定为"未完成校验"，不得当作通过。
  2. 读 `syntax_checked=false` 与 `errors` 中的 `CHECK_UNAVAILABLE` 原因。
  3. 修复运行环境（确保 `virtu_omni.serving.gbnf_grammar` 可导入），或换用官方 CIMCO 功能复核。
  4. 重新运行校验，直到 `status=success, syntax_checked=true`。
  5. 报告中如实标注校验状态，禁止写"校验通过"。
- **修复后代码/输出**：程序代码不变；正确输出应为 `{"status":"success","is_valid":true,"syntax_checked":true,"errors":[]}`（哨兵恢复后）。
- **验证方法**：检查返回四字段：`status=success` 且 `syntax_checked=true` 且 `errors=[]` 才可宣布通过；任一不满足按未通过处理。字段含义：`status=partial`=哨兵未运行；`CHECK_UNAVAILABLE`=语法检查不可用（非程序缺陷）。
- **能力边界**：**必须遵守 CAPABILITY_BOUNDARIES §三**：绝不把"未检查"读作"检查通过"。
- **证据来源**：CAPABILITY_BOUNDARIES.md §三；bridges/cimco_bridge.py:111-127

### SC-035 注释未闭合
- 场景类别 / 难度 / 适用控制系统：D 故障排查 / 中级 / 全系统
- **现场问题**：注释以 `(` 开头但漏写 `)`，导致后续代码被当作注释吞掉，语法哨兵报 "No valid G-code words" 或相关错误。
- **输入样例**（错误程序，第 5 行注释未闭合）：
```
%
O4400 (UNCLOSED COMMENT)
G90 G54 G21
T0101
M03 S1000
(DIFFICULT SETUP NOTE
G00 X50.0 Z2.0
G01 Z-10.0 F0.2
G00 Z50.0
M05
M30
%
```
- **诊断/分析**：FANUC 注释用圆括号 `(...)`，必须成对闭合。哨兵 `validate_gcode_syntax` 检测注释闭合；未闭合会使 `(DIFFICULT SETUP NOTE` 之后的行被吞为注释内容，进而 G00/G01 不被解析。桥接器对 "No valid G-code words" 会做白名单豁免（宏赋值/WHILE/END/含 `[` 的表达式），但普通 G 代码行不会豁免，故报错误。
- **处理步骤**：
  1. 用 `Ctrl+F` 搜索 `(` 与 `)`，逐行核对成对。
  2. 给 `(DIFFICULT SETUP NOTE` 补上右括号 `)`。
  3. 确认注释中不含嵌套 `(`（`(` 在注释内通常不允许嵌套）。
  4. 重新校验。
- **修复后代码/输出**：
```
%
O4400 (UNCLOSED COMMENT FIXED)
G90 G54 G21
T0101
M03 S1000
(DIFFICULT SETUP NOTE)
G00 X50.0 Z2.0
G01 Z-10.0 F0.2
G00 Z50.0
M05
M30
%
```
- **验证方法**：`validate_gcode(code)` → `errors=[]`；若注释仍闭合，errors 不再含 "No valid G-code words" 对应行。若哨兵不可用按 SC-034 处理。
- **能力边界**：静态闭合检查，不检测注释内容语义。无 B-XX 冲突。
- **证据来源**：bridges/cimco_bridge.py:97-110（哨兵调用与白名单）；https://docs.cimco.com/en/docs/edit/2026/editor-setup/file-types/colors/

### SC-044 传输失败排查（超时/流控/参数）
- 场景类别 / 难度 / 适用控制系统：E 文件对比与传输 / 高级 / 串口与 FTP
- **现场问题**：发送程序时卡住或报超时，需系统排查。
- **输入样例**（同 SC-040 程序，作为传输对象）。
- **诊断/分析**：官方参数提供排查抓手：`Handshake timeout (seconds)`（XOff/CTS Low 后等待时间，未指定则一直等 start flow）、`Delay before each line (ms)`、`Break after receiving characters`（达到字符数即结束，空则忽略）、`Flow control` 类型。FTP 侧核对 `Port` 与账号/IP。
- **处理步骤**：
  1. 核对物理连接：COM 口、波特率、数据位、校验、停止位与机床一致（7E2）。
  2. 核对流控类型：机床用 XOn/XOff 还是 RTS/CTS，选错会卡住。
  3. 设置合理的 `Handshake timeout`（如 30 s）避免无限等待。
  4. 增加 `Delay before each line`（如 10 ms）缓解机床处理慢导致的溢出。
  5. FTP 场景核对 IP/端口/用户名与远程目录权限。
  6. 用分段发送（先发小程序）定位是链路还是程序问题。
- **修复后代码/输出**：配置修正摘要（同 SC-042 模板），程序不变。
- **验证方法**：以小程序试传成功为链路正常判据；`validate_gcode(code)` → `errors=[]` 排除程序本身问题。
- **能力边界**：传输排查依赖机床侧配合；本文档不含机床内部协议细节。无 B-XX 冲突。
- **证据来源**：https://docs.cimco.com/en/docs/edit/2026/dnc-setup/standard-serial-protocol/transmit/ ；https://docs.cimco.com/en/docs/edit/2026/dnc-setup/ftp-client-protocol/port/

### SC-048 NC Function Scripts 宏脚本自动化思路
- 场景类别 / 难度 / 适用控制系统：F 批量自动化处理 / 高级 / 全系统
- **现场问题**：希望把"打开→校验→重命名→保存"的重复动作自动化，减少人为点击失误。
- **输入样例**（目标程序，同 SC-045 的 O5000）。
- **诊断/分析**：官方 `nc-functions/scripts/` 与 `scripts/writing-scripts/` 明确支持编写 NC Function Scripts；宏模板中行首 `#` 为块号占位、字面 `#` 用 `##`（官方规则）。这是 CIMCO 内建的自动化通道，区别于外部 Python 脚本。
- **处理步骤**：
  1. 在 `NC Functions → Scripts` 查看现有脚本与示例。
  2. 按 `Writing NC Function Scripts` 语法编写脚本，完成校验/重命名/保存。
  3. 宏模板中需要输出 `#` 变量时写 `##100` 避免被当块号。
  4. 在副本上试运行，确认输出无误。
  5. 固化脚本作为现场标准作业。
- **修复后代码/输出**（脚本思路伪代码，非官方脚本语法原文）：
```
FOR EACH file IN batch:
    open(file)
    result = validate_macro(current_program)
    IF result.errors NOT EMPTY: log(file, result.errors)
    rename(file, prefix + original)
    save_as(new_path)
```
- **验证方法**：脚本运行结果对照桥接返回四字段；`status=partial` 或 errors 非空的文件单独处理。脚本能力以官方 `Scripts` 文档为准。
- **能力边界**：官方 Scripts 是内建自动化；外部脚本属工程化自测（B-06）。不宣称"自动 20 次人工实操"。
- **证据来源**：https://docs.cimco.com/en/docs/edit/2026/program-tabs/nc-functions/scripts/ ；https://docs.cimco.com/en/docs/edit/2026/program-tabs/nc-functions/scripts/writing-scripts/

### SC-049 校验与传输日志分析
- 场景类别 / 难度 / 适用控制系统：F 批量自动化处理 / 中级 / FANUC
- **现场问题**：积累了一批校验/传输日志，需汇总错误类型分布，找出高频问题。
- **输入样例**（日志中一条校验返回，取自真实工具返回格式）：
```
{"status":"success","is_valid":true,"syntax_checked":true,
 "syntax_check_error":null,
 "errors":["Spindle still on at program end (no M05)."],
 "variables_count":5,"variables":["#100","#101","#102","#103","#104"],
 "line_count":27}
```
- **诊断/分析**：真实工具返回字段含义（ENG-03）：`status`=success/partial/error；`is_valid`=综合有效性；`syntax_checked`=哨兵是否运行；`errors`=问题清单；`variables_count/variables`=宏变量；`line_count`=行数。日志分析即统计 errors 中各类消息频次。
- **处理步骤**：
  1. 解析每条日志的 `errors` 数组。
  2. 按消息类型归类：`no M05`、`Unclosed WHILE DO`、`Mismatched END`、`out-of-range`、`Program end M02/M30 not found.`、`CHECK_UNAVAILABLE`、`No valid G-code words`。
  3. 统计频次，排序定位高频问题。
  4. 对 `status=partial` 的单独标记（未验证，不计入通过）。
  5. 输出月度质量报告。
- **修复后代码/输出**（报告示例）：
```
错误类型                          次数
Spindle still on ... no M05       12
Unclosed WHILE DO                  3
Program end M02/M30 not found.     2
CHECK_UNAVAILABLE                  1  (未验证)
```
- **验证方法**：报告保留原始字段，不以结论代替（EVIDENCE D-2）；`CHECK_UNAVAILABLE` 单列"未验证"类别。
- **能力边界**：日志分析是工程化自测（B-06），不冒充人工统计/外部认证。

- **现场问题**：同一产品的多个程序（不同工序/版本）需确认关键字段一致：单位（G21）、坐标系（G54）、安全 Z、收尾（M05/M30）、无残留循环。
- **输入样例**（两份程序节选）：

M05

%
```
- **验证方法**：`validate_fanuc_macro_b(P2)` → `errors=[]`；一致性脚本输出差异清单应为空。字段不含跨程序比较，须自写对比逻辑。
- **能力边界**：一致性检查是工程化自测（B-06），不冒充人工审核；静态字段比较不替代背绘/机床验证。

## 附录：校验字段与能力边界速查

### 校验返回字段含义（bridges/cimco_bridge.py::validate_fanuc_macro_b）
| 字段 | 取值 | 含义 |
|---|---|---|
| `status` | success / partial / error | success=哨兵已运行；partial=哨兵不可用（CHECK_UNAVAILABLE），不得读作通过 |
| `is_valid` | true / false | `syntax_checked and not critical`；partial 时必为 false |
| `syntax_checked` | true / false | 语法哨兵是否真正运行；false 表示语法检查未完成 |
| `errors` | 字符串数组 | 具体问题（含行号）；空数组表示本轮检查未发现问题 |
| `variables_count` / `variables` | 数字 / 列表 | 采集到的 # 宏变量数量与名称 |
| `line_count` | 数字 | 程序行数 |

**铁律**：凡称"校验通过"，必须同时给出 `status/syntax_checked/errors` 原始字段；`status=partial` 或 `errors` 含 `CHECK_UNAVAILABLE` 时一律按"未验证"处理。

### 能力边界索引
- **B-01**：机床仿真为 add-on，许可未核实→未验证（SC-025）
- **B-02**：仅文件差异对比（diff/Goto/Sync），无版本管理（SC-038）
- **B-03**：华中数控仅 ISO_G-Code 通用模板近似，非原生支持（SC-016）
- **B-04**：后处理仅 CNC-Calc，通用 CAM 后处理在 CAM 侧（SC-014/015/046）
- **B-05**：无 3D 建模，路由 AutoCAD/NX/SOLIDWORKS（SC-023/027）
- **B-06**：拟人化指标以工程化自测替代（SC-045/048/049/050）
