# 04 指令映射与考核验收规程

> 目标：让「用户随口一句话」到「工程师照着能做完」之间只有一次转换，且转换结果可被判分。

---

## 1. 统一输出格式（四段式，强制）

```
步骤 1 ｜ 路径：草图选项卡→直线
        参数：长度 50mm，角度 0°，起点与原点重合
        校验：两端点可捕捉，草图变黑（完全定义）
步骤 2 ｜ 路径：草图选项卡→智能尺寸
        参数：标注长度 50mm，从动/驱动按设计意图选择
        校验：尺寸驱动后几何随动，无过定义
```

**硬性要求**

| 要素 | 规则 |
| --- | --- |
| 步骤编号 | 从 1 连续，不跳号；分支用 `3a/3b` |
| 操作路径 | 用 `→` 连接，层级与 2021 菜单完全一致；必须能在界面逐级点开 |
| 参数配置 | 参数名 + 取值 + 单位；枚举值写全称；不写「适当」「按需」 |
| 校验要点 | 可执行（测量/检查/质量属性/视觉判据），不写「检查是否正确」 |
| 异常分支 | 每 3 步至少 1 条可触发失败与修复 |
| 版本标注 | 首次出现时注明「SOLIDWORKS 2021 SP5」 |

**反例（直接判不准确）**

- 「用拉伸命令拉一个厚度」——无参数、无路径、无校验。
- 「在插入菜单里找特征」——路径不唯一。
- 「把圆角改成 5」——未说明是半径还是直径，未说明失败回退。
- 「用 2023 的某个新功能」——版本串味，直接 0 分。

## 2. 指令映射表

### 2.1 记录结构

```json
{"id":"IM-000001",
 "text":"法兰盘上 6 个 Ø11 孔怎么均布？",
 "intent_class":"创建",
 "module":"特征",
 "target_op":"FEAT-29",
 "slots":{"hole_n":6,"hole_d":11,"pcd":120},
 "expected_output_format":"步骤编号+操作路径+参数配置+校验要点",
 "confidence":0.95}
```

### 2.2 20 类意图（覆盖率的分子）

`创建 / 修改 / 删除 / 查询 / 校验 / 导出 / 导入 / 装配 / 标注 / 配置 / 优化 / 排错 / 批处理 / 标准化 / 选型 / 计算 / 仿真 / 渲染 / 展开 / 布线`

覆盖率 = 已覆盖意图类数 / 20。要求 **≥95%**，即至少 19/20。
当前实测：**20/20 = 100%**。

### 2.3 规模与去重

- 生成：18139 条（去重后），覆盖 348 个 L3 点，平均每点 52.1 条表述。
- 去重规则：同一 `text` 只保留首条；去重前后数量写入校验报告，防止「同义改写注水」。
- 每条必须绑定 `target_op`，无绑定视为无效映射。

### 2.4 歧义与缺参处理（必须显式追问）

| 场景 | 处理 | 示例 |
| --- | --- | --- |
| 缺关键尺寸 | 追问 1 次，给出建议区间 | 「板厚多少？常用 1.5/2.0/3.0mm」 |
| 多解 | 列 2~3 个方案 + 推荐 | 「用拉伸切除或异型孔向导，推荐后者（带标准）」 |
| 危险操作 | 先确认再执行 | 「将删除 12 个特征，是否继续？」 |
| 版本不明 | 默认 2021，并声明 | 「按 2021 SP5 给出，若为其他版本请告知」 |
| 与国标冲突 | 以国标为准并说明 | 「GB 要求第一视角，你的描述是第三视角」 |

## 3. 模块阶段考核

### 3.1 流程

```
训练完成 → 抽 26 条用例（覆盖该模块 ≥80% L3 点）
        → Agent 独立输出四段式
        → 逐条判分（路径/参数/校验/异常/版本）
        → 准确率 = 全对条数 / 26
        → 100% 放行；否则补训 8h → 重考（最多 2 次）
        → 连续 2 次不过 → 回退到上一模块重训
```

### 3.2 判分口径

| 情形 | 判定 |
| --- | --- |
| 路径少一级/多一级 | 不准确 |
| 参数缺单位 | 不准确 |
| 参数值超出 2021 允许范围 | 不准确 |
| 校验点无法执行 | 不准确 |
| 无异常分支（该操作存在已知失败模式） | 不准确 |
| 出现 2022+ 命令 | 不准确且该模块整体重审 |

> 「准确率 100%」不是苛刻，而是因为下游是机床与刀具：一条错路径的代价远高于一次补训。

### 4.3 国标工程图

| 检查项 | 依据 | 判据 |
| --- | --- | --- |
| 图幅/图框 | GB/T 14689 | A0~A4 与模板一致 |
| 比例 | GB/T 14690 | 优先 1:1，标注在标题栏 |
| 视图 | GB/T 4458.1 | 第一视角，投影对齐 |
| 剖视 | GB/T 4458.6 | 剖切符号、剖面线方向正确 |
| 尺寸 | GB/T 4458.4 | 不重复、不封闭、箭头统一 |
| 公差 | GB/T 4458.5 / 1800.1 | 配合代号与偏差二选一 |
| 形位 | GB/T 1182 / 1184 | 框格、基准、未注公差声明 |
| 表面结构 | GB/T 131 | 符号朝向、统一注法 |
| 技术要求 | GB/T 4458.1 | 材料/热处理/未注圆角/未注公差/表面处理 |
| 标题栏/明细栏 | GB/T 10609.1/2 | 字段完整、件号对应 |

> 用户原文提到「GB/T 4458.6」作为工程图总体依据；严格说 4458.6 只覆盖**剖视图和断面图**，
> 视图/尺寸/公差分别对应 4458.1/4458.4/4458.5。本方案按分项条款执行，避免「一条标准打天下」的误用。

## 5. 人工实操验证与签署

每条通过机器校验的指令，仍需在 2021 原生环境实操一次，并记录：

```json
{"sample_id":"SW21-000123","op_code":"SKT-01",
 "verifier":"张三","verified_at":"2026-11-20T14:32:00+08:00",
 "result":"pass","screenshot":"evidence/SKT-01_20261120_1432.png",
 "deviation":"无","note":"菜单路径与参数均一致"}
```

| 字段 | 规则 |
| --- | --- |
| verifier | 具备 2021 使用经验的工程师，**不得与训练执行者同一人** |
| verified_at | 精确到分钟，带时区 |
| result | `pass` / `fail` / `blocked` |
| screenshot | 必须含标题栏版本 + 文件路径 + 命令面板 |
| deviation | 与指令不一致之处，无则写「无」 |

签署覆盖率进入交付门槛：**100% 才可交付**。

## 7. 问题台账与整改闭环

```json
{"id":"ISSUE-0007","found_at":"2026-11-18","source":"G2-草图",
 "issue":"等距实体失败分支写成『加大距离』，实际应减小距离",
 "severity":"major","owner":"训练执行","due":"2026-11-19",
 "action":"修正 ops_01_sketch.psv SKT-24 错误分支","status":"closed",
 "regression":"TC-000031 通过","closed_at":"2026-11-19"}
```

| 严重度 | 定义 | 时限 |
| --- | --- | --- |
| blocker | 导致错误加工/错误出图 | 当日 |
| major | 路径或参数错误 | 2 日 |
| minor | 表述/格式问题 | 5 日 |

闭环要求：**发现 → 登记 → 定责 → 整改 → 回归 → 关闭**，六步缺一不可；同类问题二次出现，升级为 blocker 并追溯审核责任。

## 8. 最终交付验收清单

### 8.1 完整性

- [ ] 12 模块三级清单齐全，无「其他」兜底项
- [ ] 训练集 ≥5000（实测 6317）
- [ ] 指令映射 ≥2000（实测 18139）
- [ ] 测试用例 ≥500（实测 524），每模块 ≥20
- [ ] 版本合规清单 + 校验报告
- [ ] 人工签署记录 100%

### 8.2 一致性

- [ ] 三套资产的 `op_code` 双向可解析（悬空引用 = 0）
- [ ] 每个 L3 点至少 1 条训练样本 + 1 条映射 + 1 条用例（实测 348/348）
- [ ] 参数域与用例取值不冲突
- [ ] 同一操作在不同文档中的路径表述完全一致

### 8.3 版本

- [ ] 界面路径白名单命中率 100%
- [ ] 2022+ token 命中 0
- [ ] 每条记录带 `version.build=29.5.0.0070`
- [ ] 截图证据可追溯到具体样本

### 8.4 判定

三项全绿 → 交付；任一红 → 阻断，整改后重跑 `gen/validate_all.py` 并重新签署。
