# 第一部分 报警处理总论

## 1.1 先分清两类"异常"

SSCNC 里的"出问题"分属两个完全不同的层级，混为一谈是排障失败的首要原因。

| 维度 | 软件级异常 | 数控系统级报警 |
| --- | --- | --- |
| 典型现象 | 双击无反应、启动闪退、登录器报错、窗口白屏/黑屏、菜单点了没反应、键位自动化失效、录制/广播异常 | 屏幕报警页出现 `O010 不正确的G代码`、`O506 超程:+`、`O2001 急停/超程英文提示` 等编号信息 |
| 归属层 | Windows 进程 / SSCNC 登录器 / MFC 界面 / 自绘画布 / 激活文件 | 被仿真的 CNC 内核（StdF0iCtrl.dll、StdFanucCtrlor.dll、StdSiemensCtrlor.dll、YJControlor.dll 等，见 S3） |
| 依据来源 | S3/S4/S5/S6/S7 + Windows 事件查看器 | S1（编号含义）+ 官方 CHM 知识库（语法）+ NC 程序文本 |
| 处理入口 | 进程、路径、权限、兼容模式、激活文件、显示设置 | 报警页、MDI 面板、程序编辑器、偏置/参数页面 |
| 会不会因换程序消失 | 不会 | 通常会（改写程序即可消除编程类报警） |
| 本文对应章节 | 第四部分 | 第二、三部分 |

**一句话判别法**：错误文字带 `O` 加三位数字、且出现在 CNC 屏幕的"报警信息"页 → 数控系统级报警；错误来自 Windows 对话框、登录器、进程崩溃或界面无响应 → 软件级异常。

## 1.2 数控系统级报警的内部再分类（FANUC 为例）

依据 S1 的编号分布 + 通用 FANUC 报警体系常识（【推理】，编号含义本身已核对）：

| 类别 | 编号区间（S1 中的实际条目） | 含义归属 | 例子 |
| --- | --- | --- | --- |
| P/S 报警（程序/设定） | 000–099、100–199 的主干 | 程序语法、G/M 代码、数据格式、子程序 | `010=不正确的G代码`、`074=非法程序号`、`077=子程序嵌套错误` |
| 宏程序报警 | 112–133 一带 | 变量、表达式、格式、调用层级 | `112=被零除`、`115=非法变量号`、`122=4重宏模态调用` |
| 刀具/ATC 类 | 150–159、210 一带 | 刀具组、T 代码、刀库 | `150=非法刀具组号`、`155=MO6中的非法T代码`、`210=不能指令M198/M099` |
| 主轴/刚性攻丝 | 190–205 一带 | S 代码、主轴方式、刚性攻丝 | `200=非法S代码指令`、`201=刚性攻丝中没有发现进给速度` |
| 超程/急停 | 506、507、2001 | 轴行程限位、急停按钮 | `506=超程:+`、`507=超程:-`、2001 英文急停/超程提示 |
| 系统/服务类 | 5000 以上 | 存储、通信、系统内部 | `5010=记录结束`、`5073=没有小数点`、`5074=地址重复错误` |

> 注意：上表的"区间"是为了便于记忆的归纳，不是 FANUC 官方分类声明；精确含义仍以 S1 逐条为准。

## 1.3 报警处理通用流程（六步法）

这套流程对软件级与系统级异常都适用，区别只在第 3 步查什么资料。

1. **取证**：先截图或抄录完整信息——编号、文字、发生时机（启动/载入程序/按循环启动/换刀/测量时）、当时所处页面与方式（编辑/MDI/自动）。
   - 系统级：抄下 `O***` 编号与整句含义；S1 只给含义，不给触发条件。
   - 软件级：记下进程名、窗口标题、是否有 Windows 错误对话框。
2. **分层**：按 1.1 的判别法确定是软件级还是系统级；系统级再按 1.2 归类。
3. **查权威定义**：
   - 系统级 → 查本文第二部分速查表（源自 S1），或 `alarms_fanuc_extracted.json`；
   - 软件级 → 查本文第四部分 + S3/S4/S5/S6/S7。
4. **定位触发源**：系统级优先看"当前执行的程序段"（哪一行 G/M 代码、哪个偏置号、哪个轴指令）；软件级优先看"启动方式 + 安装目录 + 激活文件 + 窗口状态"。
5. **最小改动验证**：一次只改一个变量（改一行程序、改一个偏置号、换一个启动方式），重新运行，观察报警是否消失。切忌同时改程序、参数、安装文件。
6. **归档**：把"编号 → 真实原因 → 有效处置"记入自己的故障库；若与本文标注不同，以实测为准，并更新"复现验证状态"。

## 1.4 报警页面的可用信息（界面文本已核对，页面交互待实测）

S9 的 `[Fanuc0iPageAlarm]` 段给出了报警相关页面与软键文本：

- 页面标签：`TITLEALARM=报警信息`、`TITLEOPRT=操作信息`、`TITLEHISTORY=报警历史`、`TITLEMSG=普通信息`、`TITLEMSGHIS=普通信息历史`。
- 软键文本：`OPRT0=选择`、`OPRT1=返回`、`OPRT2=清除`；页签含 `ALARM0=报警`、`ALARM1=消息`、`ALARM2=历史`、`MSG0=报警`、`MSG1=消息`、`MSG2=历史`。

因此排障时应同时看"报警信息"（当前报警）与"报警历史"（先前报警），并用"清除"软键清空历史后再复现，以免旧报警干扰判断。

**状态标注**：页面标签/软键为**【界面文本已核对】**（来自语言文件）；这些键在自绘画布上的实际点击位置与响应为**【待实测】**——S4 的菜单枚举不覆盖面板自绘区，S5 的 `panel_capability()` 也报告其无 Button/Static 子控件。

## 1.5 三条"不要"

- 不要看到报警就重装软件。绝大多数 `O***` 报警与安装无关，改程序即可。
- 不要用"清空 NC 代码"【实测菜单：文件→清空NC代码】代替排障——那会破坏现场，使原因无法追溯。
- 不要相信"所有 308 个编号都有中文含义"。中文库只定义了 159 条；其余编号在中文库中是空槽，本文不补写。

## 1.7 从程序段定位报警源的方法

1. **先冻结现场**：不要在报警未看清前按复位/清空，否则丢失段号信息。
2. **抄下当前段**：在 NC 程序编辑视图（`AfxFrameOrView100s`【实测菜单】）中读出报警时的程序段；若软件高亮了出错行，优先以高亮行为准【需实测：高亮行为是否存在】。
3. **拆分复杂段**：一段含多个 G/M/轴指令时，用单段方式逐段执行，定位到具体地址。
4. **对照官方含义**：拿编号到第二部分查原文，用原文中的关键词反查程序段（例如“补偿号”→找 D/H；“平面”→找 G17/G18/G19）。
5. **一次一改**：只改一个地址后再跑；若报警变化，记录“旧编号→新编号”这条线索。
6. **回到全程**：单段确认无误后再取消单段跑完整程序。单段/空运行本身不是报警号，官方库中没有对应条目（见 FAQ Q26）。

## 3.1 程序格式与地址类

### 报警 000：请关电源

- **报警号/信息**：`O000 请关电源`（S1：`000=请关电源`）。**【官方报警库定义已核对】**
- **触发原因**【推理】：官方含义直指"需要关机"，属于系统级提示而非程序语法错误。在真实 FANUC 上常与存储器/参数写入后的电源复位要求相关；在仿真环境中更可能是内核初始化或参数写入后要求重启会话。
- **标准化排查路径**：
  1. 确认当前是否刚修改过系统参数或执行过存储操作；
  2. 保存程序与偏置数据（文件→保存 / 另存为【实测菜单】）；
  3. 退出软件并重新启动，选择同一 CNC 配置；
  4. 若复现，检查安装目录是否具备写权限（见第四部分 4.3）。
- **可直接执行的解决方法**：按提示关闭仿真会话后重新启动；不要在运行中强制结束进程，先走 `文件→退出`【实测菜单】。
- **关联报警**：`100=参数写允许`、`101=请清除存储器`（S1）
- **易混淆点**：000 的官方含义是“请关电源”，与 2001 的急停/超程提示不是一回事。
- **复现验证状态**：官方报警库定义已核对；软件内触发与清除待实测复现。

### 报警 004：地址没找到

- **报警号/信息**：`O004 地址没找到`（S1：`004=地址没找到`）。**【官方报警库定义已核对】**
- **触发原因**【推理】：程序段中出现了系统不认识的地址字母，或地址字母与数字之间格式不合法（例如把 `X` 写成非 ASCII 相似字符、全角字母）。
- **标准化排查路径**：
  1. 检查程序段中是否有非标准的字母（常见：中文输入法全角 `Ｘ／Ｙ／Ｚ`、小写误用）；
  2. 用纯文本方式重新输入该行，避免从网页/Word 复制带隐藏格式；
  3. 确认所选系统支持该地址（例如某些系统不识别某些第四轴地址）；
  4. 重新载入程序验证。
- **可直接执行的解决方法**：把非法地址改为当前系统支持的 ASCII 大写地址；重新通过 `文件→打开`【实测菜单】载入程序。
- **关联报警**：`009=输入非法地址`、`5074=地址重复错误`（S1）
- **易混淆点**：004 偏“地址未被识别”，009 偏“输入了非法字符”，常连锁出现。
- **复现验证状态**：官方报警库定义已核对；软件内触发与清除待实测复现。

### 报警 005：地址后面无数据

- **报警号/信息**：`O005 地址后面无数据`（S1：`005=地址后面无数据`）。**【官方报警库定义已核对】**
- **触发原因**【推理】：写了地址字母但未给数值，例如 `G01 X F100`（X 后缺数值）、`G04 P`（P 后空）。
- **标准化排查路径**：
  1. 找到报警段，逐个地址检查其后是否有数字；
  2. 重点看行尾地址、被回车截断的地址、连续两个地址中间漏值；
  3. 检查是否有 `N` 行号后直接跟下一行而漏写指令；
  4. 补全数值后重跑该段。
- **可直接执行的解决方法**：为每个地址补全合法数值；若该地址本意是注销（如 `G90` 单独成段），确认是否误留了裸地址字母。
- **关联报警**：`003=数字位太多`、`5073=没有小数点`（S1）
- **易混淆点**：先判断“有没有数值”再判断“数值格式”，顺序不能反。
- **复现验证状态**：官方报警库定义已核对；软件内触发与清除待实测复现。

### 报警 007：非法使用小数点

- **报警号/信息**：`O007 非法使用小数点`（S1：`007=非法使用小数点`）。**【官方报警库定义已核对】**
- **触发原因**【推理】：在不允许小数点的地址上写了小数点。典型为整数型地址：刀具号 `T`、补偿号 `D/H`、子程序号 `P`、循环次数、G 代码序号等。
- **标准化排查路径**：
  1. 找到报警段中所有含 `.` 的地址；
  2. 把 `T01.`、`D02.`、`P1000.` 等整数地址的小数点去掉；
  3. 若确需小数（坐标、F、S），确认系统是否要求必须带小数点（这类系统反而会报"没有小数点"，见 5073）；
  4. 重跑验证。
- **可直接执行的解决方法**：`T01.` → `T01`；`D02.` → `D02`；保留 X/Y/Z/F/S 的小数点。
- **关联报警**：`5073=没有小数点`（S1）
- **易混淆点**：007 是“不许带小数点”，5073 是“必须带小数点”，方向完全相反。
- **复现验证状态**：官方报警库定义已核对；软件内触发与清除待实测复现。

## 3.7 高频误区澄清

1. **误区：报警号是“错误等级”。** 不是。S1 中编号只是官方索引键，`506/507` 是超程、`2001` 是急停/超程，并不存在“数字越大越严重”的规律。
2. **误区：中文库应该有 308 条含义。** 实际 `[ALARM]` 段只有 159 条（见 0.2）。缺失的 161 个编号本文不补。
3. **误区：007 和 5073 是同一件事。** 007 是“非法使用小数点”（不该有），5073 是“没有小数点”（该有却没有），方向相反。
4. **误区：刀补未设与补偿号非法是同一报警。** 前者是 `029=非法偏置值`，后者是 `030=非法补偿号`，S1 中是两条独立条目。
5. **误区：单段/空运行会产生报警。** 官方库中没有“单段”或“空运行”编号条目，它们是调试手段（FAQ Q26）。
6. **误区：清掉报警就等于修好。** 必须先定位触发段；用 `文件→清空NC代码`【实测菜单】会丢失现场。
7. **误区：2001 是中文报警。** 官方字段本身是英文长句，本文照录，未翻译替换。
8. **误区：面板键能用 PostMessage BM_CLICK 触发。** S5 的 `panel_capability()` 已明确报告自绘画布无 Button/Static 键位，该方式不可行。

## 3.8 深度解析小结

- 上述 30 条全部为 **【官方报警库定义已核对】**，编号与含义可在第二部分的速查表中逐条反查。

# 第四部分 软件运行异常（进程 / 窗口 / 面板 / 自动化）

> 本部分全部基于 S3（实测索引）、S4（实测菜单）、S5（桥接脚本）、S6（启动探针）、S7（安装说明原文）。与第三部分不同，这里的“实测”指**本环境对该软件外壳的真实观察**，不是对某条报警的复现。

## 4.1 必须先理解的三条边界

1. **面板是自绘画布，不是标准控件树**。【实测经验，S5】`SSCNCBridge.panel_capability()` 枚举窗口子控件，只把 `class in ("Button","Static")` 且带文本的控件视为可寻址键位；实测 CNC 面板无此类子控件，因此返回 `status: unsupported`，理由为 `self-drawn CNC canvas: no Button/Static key controls`。
   - 推论：**不能**用 `PostMessage(BM_CLICK)` 去“按”面板键；`press_panel_key()` 在 unsupported 时会明确拒绝并返回 `{"status":"unsupported", ...}`，而不是假装点击成功。
   - 面板键位自动化只能走**坐标点击**；坐标需自行截图标定，S4 的菜单枚举**不覆盖**面板区。
2. **启动是 explorer 派生 + 多进程**。【实测经验，S3/S6】真实入口是 `E:\仿真软件\2斯沃7.2（内含安装说明）\SSCNC\CNCLogin.exe`（桌面快捷方式 `E:\SSCNC\CNCLogin.exe` 已失效）；探针用 `subprocess.run(["explorer.exe", EXE])` 派生，以避免沙箱子进程被回收。登录器 `CNCLogin` 与仿真主进程 `sscnc` 同时存在，主窗口类 `ClassName_Swansoft_CNC_Simulation`。
3. **安装目录与激活文件**。【S7 原文核对】安装说明要求运行 `SSCNC7.2.2.0Setup` 安装，随后把“激活补丁”文件夹内的两个文件复制到安装目录；默认路径 `C:\Nanjing Swansoft\SSCNC`，自定义安装则在所选路径。忘记路径时，可通过桌面图标右键→属性→“打开文件位置”定位。
   - 本文只如实转述该安装说明的存在与步骤，**不提供任何绕过软件授权的技术细节**。

## 4.2 启动类异常

### 4.2.1 双击图标没反应 / 闪一下就退出

- **可能原因**【推理，部分依据 S3/S6/S7】：
  1. 用了失效的桌面快捷方式 `E:\SSCNC\CNCLogin.exe`；
  2. 激活文件未放到安装目录，登录器自检失败；
  3. 安装目录无写权限（程序需写参数/偏置/记录）；
  4. 直接 `Popen` 启动的子进程被父进程退出连带回收。
- **排查路径**：
  1. 核对 exe 路径是否存在（bridge 的 `launch()` 会返回 `executable not found`）；
  2. 用 explorer 派生方式启动（S6 探针做法）；
  3. 以管理员身份运行，检查安装目录写权限；
  4. 用任务管理器确认 `CNCLogin` / `sscnc` 进程是否短暂出现。
- **解决**：改用真实路径 `...\SSCNC\CNCLogin.exe`；按 S7 确认激活文件在正确目录；对安装目录赋予当前用户写权限。
- **状态**：路径与 explorer 派生为**实测已核对**；权限/激活导致的闪退为**需实测**。

### 4.2.2 登录器能开，选完系统后进不去主界面

- **可能原因**【推理】：`general.ini` 中 `CNC=37`，系统配置项 `CNC1..CNC37` 对应各自 `DIRn=FANUC\...\sscnc.exe`；某个具体系统的 `sscnc.exe` 缺失或损坏会导致主窗口起不来。
- **排查路径**：
  1. 打开 `SSCNC\common\general.ini`，找到所选系统对应的 `DIRn`；
  2. 检查该相对路径下的 `sscnc.exe` 是否存在；
  3. 换一个系统配置尝试，判断是否只有个别系统失败；
  4. 查看 Windows 事件查看器应用程序日志。
- **解决**：改用可用的 CNC 配置；必要时重新安装并确认激活文件到位。
- **状态**：`CNC=37` 与配置结构为**实测已核对**（S3/S8）；具体失败成因需实测。

### 4.2.3 版本/更新检查异常

- **事实**：`general.ini` 含 `UPDATEURL=http://www.swansc.com/download/update.txt`，菜单 `帮助→检查更新`【实测菜单】存在（S4）。
- **排查**：离线环境或 DNS 失败会导致检查更新无响应；这不影响本地仿真。
- **解决**：离线使用时忽略更新检查；不要因更新失败而重装。
- **状态**：配置项与菜单项为**实测已核对**；网络失败表现需实测。

## 4.3 激活补丁相关异常

- **事实【S7 原文核对】**：安装说明明确要求把激活补丁文件夹里的两个文件复制到安装目录（默认 `C:\Nanjing Swansoft\SSCNC`，或自定义安装路径）。
- **常见异常与排查**【推理，需实测】：
  1. **复制到错误目录**：快捷方式指向的路径与实际安装目录不一致 → 用“桌面图标右键→属性→打开文件位置”重新定位；
  2. **只复制了一个文件**：说明要求“两个文件” → 核对源文件夹与目标目录的文件数量；
  3. **权限不足导致复制失败**：以管理员身份复制，确认目标目录可写；
  4. **升级/重装后失效**：重新安装后需重新放置文件 → 按 S7 步骤重做。
- **状态**：安装说明内容为**安装说明原文已核对**；上述异常场景为**需实测**（本环境未逐一触发）。

## 4.5 面板无响应 / 键位自动化失败

- **典型失败模式**：脚本调用 `press_panel_key("循环启动")` 返回 `unsupported`，或返回 `not_found`。
- **原因**【实测经验，S5】：面板无 Button/Static 子控件，`panel_capability()` 返回 unsupported；即便某些容器被识别，`key_like` 列表为空也会触发 not_found。
- **排查路径**：
  1. 先调用 `panel_capability()` 看 `status` 与 `reason`，不要直接点；
  2. 若 `unsupported`，停止用控件文本寻址，改走坐标点击（需自行截图标定）；
  3. 若 `not_found`，打印 `cap["key_like"]` 看实际可寻址键位；
  4. 若窗口未找到，返回 `not_running`，先按 4.4 定位窗口。
- **解决**：接受“文本寻址不可用”这一事实，把自动化策略改为坐标点击 + 图像校验；不要试图给自绘面板发 `BM_CLICK`。
- **状态**：**实测已核对**（S5 代码与 SOURCE_INDEX 结论一致）；具体坐标值未实测。

# 第五部分 FAQ（48 条）

> 标注说明：凡路径来自 S4 者标【实测菜单】；面板操作一律写“在面板上按…”，属自绘区【桥接边界】；报警含义来自 S1。FAQ 中的操作步骤以一手资料为准，未覆盖处明确说“需实测”。

## A. 系统与启动（Q1–Q7）

**Q1：SSCNC 7.2.2.0 的真实安装路径和入口是什么？**
入口是 `E:\仿真软件\2斯沃7.2（内含安装说明）\SSCNC\CNCLogin.exe`，桌面上的 `E:\SSCNC\CNCLogin.exe` 快捷方式已失效（S3）。安装目录下按系统分 `FANUC\FANUC0iM\sscnc.exe` 这类结构（S8 的 `DIRn`）。

**Q2：软件支持哪些数控系统？**
`general.ini` 中 `CNC=37`，共 37 个配置，含 FANUC 0MD/0TD/0iM/0iMF/0iT/0iTF/18M/18T/18iM/18iT/21iM/21iT、Mazak、SINUMERIK 801/802S/802C、MITSUBISHI E60/E68、FAGOR8055、HEIDENHAIN iTNC530、华中 HNC-21M/21T/22T、KND、GREAT、GSK、DASEN、WA、RENHE、SKY 等（S3/S8）。

**Q3：怎么切换系统？主菜单里为什么找不到？**
系统选择发生在登录阶段（`CNCLogin.exe`），不在主窗口 9 大菜单里（S3）。要换系统，退出会话回到登录器重新选择配置。

**Q4：为什么我用脚本启动后窗口很快消失？**
可能是子进程被父进程退出连带回收。S6 的探针使用 `subprocess.run(["explorer.exe", EXE])` 派生来规避；建议照此方式启动（S6，实测已核对）。

**Q5：双击没反应怎么排查？**
依次查：exe 路径是否正确 → 激活文件是否在安装目录（S7）→ 目录写权限 → 任务管理器中 `CNCLogin`/`sscnc` 是否短暂出现（见 4.2.1）。

**Q6：登录器和仿真主进程是什么关系？**
实测为多进程：`CNCLogin` 登录器 + `sscnc` 主进程；主窗口类名 `ClassName_Swansoft_CNC_Simulation`（S3）。排障时应同时看两个进程。

**Q7：安装说明里的激活文件要放哪里？**
按 S7 原文，把激活补丁文件夹里的**两个文件**复制到安装目录；默认 `C:\Nanjing Swansoft\SSCNC`，自定义安装则放进你选的路径。找不到目录时用桌面图标右键→属性→打开文件位置（S7，原文已核对）。

## B. 对刀与刀补（Q8–Q16）

**Q8：对刀仪/寻边器在哪里选？**
`机床操作→Z向对刀仪选择(100mm)`、`机床操作→寻边器选择`、`机床操作→基准芯棒选择`【实测菜单】。

**Q9：工件坐标系 G54–G59 怎么设？**
坐标系属面板/OFFSET 页面，不在菜单枚举内【桥接边界】。S5 的桥接脚本把 `wcs_target` 默认写为 `G54`，可用 `calculate_tool_offsets()` 计算偏置表再手工录入。

**Q10：刀具在哪选？**
`机床操作→选择刀具`【实测菜单】。

**Q11：铣刀刀具半径补偿用哪个 D 号？**
D 号与程序中 `D01`/`D02` 对应，在偏置页面录入实际半径。补偿号非法会触发 `O030`；偏置值非法触发 `O029`（S1，官方定义已核对）。

**Q12：车床刀尖方位号（象限）怎么定？**
S5 的 `calculate_tool_offsets()` 实现中：`3`=外圆车削、`2`=内孔镗削、`8`=螺纹，刀具号格式 `T{t:02d}{t:02d}`（如 T0101）。这是桥接脚本的实测实现【实测经验】，不是报警库内容。

**Q13：刀补在圆弧段启用会怎样？**
官方库有 `034=圆弧指令时不能起刀或取消刀补`、`041=刀尖半径补偿中可能产生过切`（S1）。应在直线段 G01 上启用/取消刀补。

**Q14：为什么改了刀补但加工结果不变？**
先确认程序实际调用的 D/H 号与修改的号一致；再确认修改已写入且没有在程序段中被重新覆盖。具体偏置页面操作需实测。

**Q15：Z 向对刀仪 100mm 是什么意思？**
S4 菜单原文为 `Z向对刀仪选择(100mm)`，表示可用的对刀仪规格之一；具体使用步骤官方 CHM 有主题，菜单只负责“选择”。

**Q16：刀补和磨损补偿有什么区别？**
S5 的 `calculate_tool_offsets()` 注释提到计算 geometry 与 wear offset（几何/磨损），但软件内具体页面字段需实测确认，本文不展开。

S3 记录的路径：`E:\新建文件夹 (3)\09_SOFTWARE_OFFICIAL_SAMPLES\05_SSCNC_SWAN_SIMULATION`，按系统分目录，每例含 `config.ini`、`offset.dat`、`params.lib`、`prglib.lib`、`*.cnc`。

**Q19：怎么清空当前 NC 代码？**
`文件→清空NC代码`【实测菜单】。注意：会破坏现场，排障前先备份。

**Q20：程序保存/另存为在哪？**
`文件→保存`、`文件→另存为`【实测菜单】。

**Q21：报警说“未发现程序号”怎么办？**
对应 `O059`（S1）。检查程序首行是否有 `O####`，是否已打开载入，调用端 O 号是否一致（见 3.3）。

**Q22：程序号写 `O1` 可以吗？**
不建议。`O074=非法程序号`（S1），应使用系统允许范围内的编号，如 `O0010`；具体范围查官方 CHM。

**Q23：主程序调用子程序怎么写？**
用 M98 / M99，但本环境未实测该系统的具体格式；官方库有 `077=子程序嵌套错误`、`078=没有找到程序号`（S1）。请查对应系统官方 CHM。

**Q24：从网页复制程序后进软件报“地址没找到”？**
可能是全角字母或隐藏格式。对应 `O004`/`O009`（S1）。用纯文本重新输入 ASCII 大写地址（见 3.1）。

**Q25：宏程序报警去哪查？**
S1 宏类条目包括 `112=被零除`、`114=宏程序中格式错误`、`115=非法变量号`、`122=4重宏模态调用` 等；先在第二部分速查表按号查含义，再看对应宏段。

## D. 仿真运行（Q26–Q33）

**Q26：什么是“单段/空运行”？本文把它列为报警了吗？**
单段/空运行是调试手段，不是报警号；官方库中**没有**“单段/空运行”编号条目。本文不杜撰，推荐在调试时用单段逐步验证报警段（详见 1.3 第 5 步）。

**Q27：按循环启动后没动静，先看什么？**
先看报警页是否有 `O***`（S9 页面文本：报警信息/报警历史）；再看是否处于正确方式（编辑/MDI/自动），面板方式键属自绘区【桥接边界】。

**Q28：为什么一运行就“超程:+”/“超程:-”？**
对应 `O506`/`O507`（S1）。检查坐标轴位置、G54 偏置、刀长补偿方向、工件装夹（见 3.4）。

**Q29：急停没复位是哪条报警？**
官方库 `2001` 的英文原文明确提到急停与轴超程（S1，原文照录）。解除急停与超程后再回零。

**Q30：冷却液/舱门/ACT 显示在哪控制？**
`机床操作→冷却液调整`、`机床操作→舱门`、`显示模式→刀具交换装置(ACT)显示`【实测菜单】。

**Q31：怎么看刀轨？**
`显示模式→显示刀轨`、`显示模式→显示刀位号`【实测菜单】。

**Q32：为什么仿真画面很卡？**
可尝试关闭 `显示模式→显示铁屑`、`显示冷却液`、`透明显示`、`显示透明刀具` 等【实测菜单】逐项排查；硬件加速/显卡驱动因素需实测。

**Q33：加工声效怎么关？**
`显示模式→加工声效`【实测菜单】。

## E. 测量（Q34–Q38）

**Q34：工件测量有哪些功能？**
`工件测量→刀路测量(调试)`、`特征点`、`特征线`、`距离`、`角度`、`测量退出`【实测菜单】。

**Q35：测完怎么退出测量？**
`工件测量→测量退出`【实测菜单】。

**Q36：测量定位对话框在哪？**
S4 的子窗口列表含 `#32770 进度信息 / 测量定位 / 考试 / 习题 / 冷却液软管调整 (对话框资源)`【实测菜单/实测窗口】。

**Q37：测量能直接改刀补吗？**
本环境一手资料未覆盖该交互，需实测；不要假定测量值会自动写回偏置。

**Q38：刀路测量(调试)和普通测量区别？**
菜单原文为“刀路测量(调试)”，暗示面向刀具路径调试，但具体差异未在 S1–S9 中定义，需实测。

## F. 报警（Q39–Q44）

**Q39：报警编号和含义从哪里来？**
唯一来源 `fanuc_alarmlist_cn.ini` 的 `[ALARM]` 段（S1），GBK 编码，159 条有含义条目，已导出为 `source/alarms_fanuc_extracted.json`。本文第二部分即其全量表格。

**Q40：速查表为什么只有 159 条，不是 308 条？**
因为中文库 `[ALARM]` 段只定义了 159 条含义；`[NUM]` 段 308 个编号中有 161 个在中文库里没有含义文本。本文不杜撰缺失含义（见 0.2）。

**Q41：报警号 2001 为什么是英文？**
S1 该条官方字段本身就是英文长句（急停/超程提示），本文按原文照录（见 3.4）。

**Q42：有 023、040 这些编号，为什么它们不在 308 编号列表里？**
它们只出现在 `[ALARM]` 段而在 `[NUM]` 显示列表中未列，共 12 条。官方文件既然定义了含义，本文即按官方定义收录（见 0.2）。

**Q43：怎么清除报警历史？**
S9 的 `[Fanuc0iPageAlarm]` 有软键 `OPRT2=清除`，页面含“报警历史”。**【界面文本已核对】**；实际点击位置在自绘面板上，需坐标标定【待实测】。

**Q44：报警处理完还是反复出现怎么办？**
按 1.3 六步法：先确认报警号是否真的清除（看报警历史），再单段运行定位具体程序段，一次只改一个变量。不要用清空代码掩盖问题。

## G. 网络考试与其他（Q45–Q48）

**Q45：网络版习题/考试入口在哪？**
`习题与考试→习题(网络版)`、`考试(网络版)`、`工件信息上载(网络版)`【实测菜单】（S4）。

**Q46：考试相关对话框有什么特征？**
S4 子窗口列表含 `#32770 … 考试 / 习题 … (对话框资源)`；另有 `msctls_statusbar32` 状态栏。

**Q47：网络功能连不上，可能是软件坏了吗？**
`general.ini` 含 `UPDATEURL`（S8），帮助菜单有 `检查更新`【实测菜单】；网络版功能依赖网络服务，离线失败不等于软件故障。具体服务端地址与协议未在 S1–S9 中定义，需实测。

**Q48：录制/广播在哪里？为什么脚本找不到按钮？**
S4 实测工具栏含 `录制`、`广播` 两个工具栏，所以它们存在；但 S5 的 `panel_capability()` 证明面板无 Button/Static 键位，且 S4 未枚举工具栏按钮的子控件文本，因此按文本寻址会失败。定位请按 4.6 的思路实测。
