# 第一部分　考核体系总览

## 1.1 考核目标

本考核体系服务于斯沃数控仿真软件（SSCNC 7.2.2.0）教学闭环，目标有四：

1. **知识覆盖可度量**：用 134 条客观用例覆盖软件认知、菜单、坐标、刀具、G/M 代码、面板、报警、铣削、车削、SOP 十大功能域。
2. **操作能力可分级**：把"会用软件"拆成 L1 认知 → L2 操作 → L3 排障 → L4 综合四级，逐级验收。
3. **判断有据可查**：每条用例带 `verified` 证据等级与 `source` 一手来源，做到"答案可追溯"。
4. **验收口径可复跑**：判分链路脚本化，版本迭代后可回归测试。

## 1.2 能力等级定义

| 等级 | 名称 | 能力描述 | 典型行为 | 对应考核方式 | 主要对应用例类别 |
| --- | --- | --- | --- | --- | --- |
| L1 | 认知 | 识记软件实体、版本、术语、菜单名、代码含义 | 说出版本号 7.2.2.0、指出 G41 为左补偿 | 笔试客观题 | 软件认知、实测菜单、报警知识（部分） |
| L2 | 操作 | 在仿真软件中按标准流程完成单项操作 | 选机床、装夹毛坯、对刀、导入 NC、单段/自动仿真、测量 | 实操任务 + checklist | 坐标系与对刀、仿真操作与面板、STEP/SOP |
| L3 | 排障 | 识别报警与异常，定位原因并给出处置 | 超程、刀补错误、面板无响应时判断与恢复 | 故障场景处置 | 报警知识、仿真面板（部分） |
| L4 | 综合 | 从图纸到成品独立完成完整零件加工验证 | 铣削件 + 车削件端到端加工并自检 | 端到端任务 | 铣削场景、车削场景、STEP/SOP |

> 等级递进关系：L1 是 L2 的前提，L2 是 L3 的前提，L4 要求 L1–L3 全部达标。

## 2.5 用例格式规范

每行一个 JSON 对象，字段定义如下：

| 字段 | 类型 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- | --- |

| `verified` | 字符串 | 是 | 证据等级 | `measured` |

**真实样例（原文，逐字取自 jsonl 第 1 行）**：

```json
{"id": "A01", "category": "软件认知与系统选择", "scene": "通用", "difficulty": "基础", "question": "软件当前版本号", "options": ["SSCNC 7.2.2.0", "SSCNC 6.5.3", "SSCNC 9.0", "VERICUT 9.6"], "answer": "A", "source": "实测/安装方法.txt + general.ini", "points": 1, "verified": "measured"}
```

**扩展新用例的约束**：ID 不与现有 134 个重复；`category` 必须取自 2.2 表的 10 个中文名；`verified` 必须取自三档；`source` 必须指向 `SOURCE_INDEX.md` 列出的一手资料；`points` 统一为 1。

## 2.6 如何运行判分

以下命令读取 `sscnc_testcases.jsonl` 与 `answer_key.json` 进行客观题判分（在 `ssnc_teaching` 目录下执行）：

```bash
python -c "
import json
cases=[json.loads(l) for l in open('tests/sscnc_testcases.jsonl',encoding='utf-8') if l.strip()]
key=json.load(open('tests/answer_key.json',encoding='utf-8'))
right=sum(1 for c in cases if key.get(c['id'])==c['answer'])
print('用例总数:',len(cases))
print('判分一致数:',right)
print('一致率: %.1f%%' % (100.0*right/len(cases)))
"
```

> 说明：上面这段比较的是"用例自带答案"与"答案键"的一致性，得到 100% 属预期（实测 134/134），它验证的是**数据链路**，不是考生得分。若要给考生答卷判分，应把考生答案构成 `{id: 字母}` 后替换 `c['answer']` 参与比较。

检索式覆盖自检（另一口径）直接运行：

```bash
python scripts/run_self_assessment.py
```

## 5.2 检索式自检的口径与局限（必须理解）

| 项目 | 说明 |
| --- | --- |
| 它是什么 | 把每条用例"正确选项文本"拆成中文/英数片段，在 docs/evidence/source 语料中做字符串命中，**近似判断**答案是否有文档支撑 |
| 它不是什么 | **不是**真实软件操作考核，**不是**人工评审，**不能等同于准确率** |
| 为什么低于 98% | 关键词逐字匹配会漏掉同义表述；standard 类属外推，语料本就可能没有原句 |
| 正确用法 | 作为"文档支撑覆盖度"的体检工具，发现需补文档或需标注外推的用例 |
| 错误用法 | 把 87.3% 当作"体系准确率"，或据此宣称"已达标/已复现报警" |

## 5.3 如何扩展用例

1. 在 `sscnc_testcases.jsonl` 末尾追加一行 JSON，字段按 2.5 规范填全（ID 不重复、category 取 10 类之一、verified 取三档之一）。
2. 在 `tests/answer_key.json` 增加 `"新ID": "答案字母"` 条目。
3. 运行 `python scripts/validate_testcases.py` 校验格式（如脚本存在）。
4. 重跑 `python scripts/run_self_assessment.py`，对比覆盖率是否下降；下降则说明新用例缺乏文档支撑，需补一手资料或调整 `source`。
5. 若是新增类别，需同步更新第二部分 2.2 分布表与第三部分考核抽取方案。
